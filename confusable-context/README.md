# confusable-context — 形近对上下文消歧

刻本里有几对字反复出现、字形层再准也难分——**入/人、日/曰、論/諭**、
而/面、遺/還、曾/會……用户 2026-08-26 提的问题是「这个时候要借助
上下文」，并指了两条路：n-gram 语言模型，和大模型直接读上下文。
这一集就是用来量这两条路到底行不行的。

## 题面

一题 = 一个待定字位。给出：

* 本列 OCR 转写（目标位挖成 `△`）
* 本列整理本参照（**同一位也挖成 `△`**）
* 前列、后列的文本
* 两个选项（该字所属形近对的两个成员）

二选一。不给字形候选、不给覆盖率——这一集单独量的是**纯上下文**的
判别力，字形信号混进去就说不清是谁的功劳。

## 三道防线（这一集最要紧的东西）

**一、金标只收人裁。** 人是看着字形定的，与 n-gram（在整理本上训练）、
与整理本对齐通道都无关，是唯一对各臂都中立的真值。自动进库的字多数
由 align（整理本）锚定，拿它当金标去考一个在同一语料上训练的 LM，
等于让考生带着答案进考场。

**二、参照文本也要挖空。** `align.char is None`（管线没锚上）**不等于**
整理本那一位是空的——实测 43 条难档里仍有 12 条参照文本直接写着答案。
两列按位等长对齐（实测 161/161），所以同一个下标挖两次。

**三、n-gram 臂必须报 heldout 口径。** 把所有测试列的整理本原文从训练
语料里剔掉再训。不剔（`--mode book`）在送分档上是 **100%**——那是把
原文背下来了，不是学会了。两个口径的落差就是记忆的贡献。

## 首轮结果（2026-08-26 二次核对后，n=154）

| 臂 | 真难档 | 送分档 | 合计 |
|---|---|---|---|
| 多数类基线 | 96.9% | 70.5% | 76.0% |
| 字形层 top-1 | 71.9% | 62.3% | 64.3% |
| OCR | 62.5% | 67.2% | 66.2% |
| **n-gram(3) heldout** | 87.5% | 97.5% | **95.5%** |
| **大模型（盲测）** | 93.8% | 100.0% | **98.7%** |

两条路都成立，且都远超字形与 OCR。逐对明细见 `baseline_r1.json`。

## ⚠ 已/巳：v1.0.0 说「治不了」是错的——那是金标本身被字形污染了

第一版评测发现已/巳这一对所有臂都卡在 62~69%，写成了「这一对压根不该
问上下文」。**这个结论是错的**：13 条人裁金标里有 4 条是**当时的人**
（不是刻工）照着刻本封口字形判的，不是照文意判的——「實在流傳巳久」
「書籍巳屬不少」这类明显是「已经」语义的位置被判成了「巳」，纯粹因为
刻本上那一笔是封口的。

用户看完 己/已/巳 混用的历史考据（见下）后定：**字形不重要，一律以
上下文文意为准**，并要求把此前按字形判的改回来。用
`scripts/correct_admission.py` 逐条核对 align/图块改判后（4 条
巳→已，另 1 条巳→己——`vol01:21:3:19`「因己身」整理本本来就是「己」，
超出已/巳二元，不算在这个 pair 里），重测：

| 臂 | 已/巳（n=12）|
|---|---|
| 多数类基线 | 100%（这批样本碰巧全是「已」）|
| 字形层 top-1 | **67%**（低于多数类基线——字形在这里是负资产）|
| OCR | 92% |
| n-gram | 83% |
| 大模型 | 92% |

字形层不但没赢，反而**输给瞎猜**。这是当初「治不了」结论的真正原因：
不是上下文方法不行，是拿被字形污染的金标去考它们，考卷本身就是错的。

**这批样本的多数类基线 100% 是巧合，不是「已/巳 已解决」**——巳仍有
真实存在的场景（干支纪年纪日），这 12 条恰好没碰上。等审到真正的巳
用例，才能验证上下文方法能不能正确转向选巳。

## 己/已/巳 混用的历史考据（回答「这是不是某朝代特定用法」）

已/巳字源上本来就是同一个字（甲骨文同形，「已」由「巳」分化）——现代
课堂教的「己不封口、已半封口、巳全封口」是**今人总结的辨认口诀，不是
古人的书写规矩**。北师大出版科学研究院的校对研究直接点名：宋元刻本
已经混，**清代《欽定四庫全書》本——己已巳仍然混用**，光绪翻刻本也混。
`config/dicts/variants.tsv` 目前没收这条异体关系（该文件只管字形层
标签归一，不影响本集的题面/金标）——已单独在管线的
`SEMANTIC_MERGED_PAIRS` 里登记，供上下文/语言模型判定豁免 near_form
字形护栏用，详见下方「落地」。

己不一样——它是**真的另一个字**（自己 vs 已经/地支），不是同词异写。
`vol01:21:3:19` 实锤过己被错认成巳（align 与图块目视双证），已加进
`match.NEVER_MATCH_FAMILIES`（字形护栏，防形状判据认错），但**没有**
加进 `SEMANTIC_MERGED_PAIRS`——上下文通道对它照样要拦，仍然人审。
实测把己拉进这个测试集会生成一堆多数类基线 100% 的送分题（己/已、
己/巳 共 9 题，没有真实歧义可测），已用 `_EXCLUDE_FROM_SET` 摘掉。

## 落地：已经接进生产准入规则

`open_guji_cv/clustering/seeding.py` 新增 `SEMANTIC_MERGED_PAIRS`
（当前只有 `{("已","巳")}`）：上下文通道的 near_form 护栏加了一条例外
——命中的字若在这张表里，不拦，照走 `ctx_decider` 按文意判断，margin
过阈（默认 0.70）才自动进库，够不着阈值仍然人审。字形层
`NEVER_MATCH_FAMILIES`（`GlyphMatcher` 用，防止**形状判据**自己互认）
完全不动。单测
`test_semantic_merged_pair_context_bypasses_near_form`
（`tests/clustering/test_seeding.py`）覆盖：near_form + signal_conflict
+ replace_align 三条疑问全命中的场面，只因为字属于 SEMANTIC_MERGED_PAIRS
就照走 context 通道自动进库。

## 复现

```bash
cd open-guji-cv
# n-gram 臂（三种语料口径）
PYTHONPATH=. python scripts/eval_confusable_lm.py <dataset>/confusable-context/cases.json \
    --book-corpus corpus/zongmu_wuyingdian_reference.txt \
    --general-corpus corpus/external/daizhige_zhaoling.txt \
    --mode heldout --out /tmp/lm.json
# 各臂对答案（答案文件到这一步才读——盲测的意义全在先后顺序上）
PYTHONPATH=. python scripts/score_confusable.py <dataset>/confusable-context/answer_key.json \
    --cases <dataset>/confusable-context/cases.json --lm /tmp/lm.json
```

重建题面（队列增长/改判后重扩集）：
`scripts/build_confusable_set.py output/vol01`，
盲测题面导出：`scripts/export_confusable_prompt.py`。
改判已入库人裁字位（字形改文意）：`scripts/correct_admission.py`。

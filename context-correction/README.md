### 消融：三个机制各值多少（本书权重固定 0.75）

| 配置 | 增益 | 救回 | 改坏 | 有害翻转 |
|---|---|---|---|---|
| 只有 LM 混合 | +2.36% | 609 | 195 | 1.26% |
| ＋本版用字习惯（无闸门）| +2.68% | 804 | 334 | 2.15% |
| ＋本版用字习惯（闸门 0）| +3.30% | 787 | 207 | 1.33% |
| **＋本版用字习惯（闸门 2，默认）** | **+3.35%** | 801 | 213 | **1.37%** |
| ＋本版用字习惯（闸门 10）| +3.21% | 803 | 239 | 1.54% |
| 再＋簇级边缘化（全簇）| +3.08% | 868 | 328 | 2.11% |
| 再＋簇级边缘化（只对 size≥2）| +3.26% | 813 | 240 | 1.55% |

两条结论：

**1. 本版用字习惯要带证据强度闸门。** 无闸门时它几乎白干：多救回 195
条、多改坏 139 条，净赚 56 条却把有害翻转翻了近一倍。闸门（组内非主形
在本版语料的频次 ≤2 才动手）把「本版两个形都在用」的组挡在外面——那种
情况不是用字习惯，是本来两个字都有，动它就是瞎猜。加了闸门之后这一步
值 **+0.99pp**，且有害翻转几乎不涨。

**2. 簇级边缘化在本集上是净有害的**（−0.27pp，有害翻转 1.37%→2.11%），
默认已关。这与旧结论「零劣化」相反——旧结论出自**双来源共识黄金集**，
而那个黄金集本身按候选一致性构建，簇级边缘化正是让簇内更一致，是自证。
根因是聚类不纯：`char-ocr` 上用纯金标量到 **31.3% 的多元簇不纯**，
13.76% 的多元簇实例注定错。**这个机制不是没用，是当前聚类质量撑不起
它**；聚类纯度上去后应当重测。

### λ（OCR 项 vs LM 项的配比）

首版在 book9 上测过，结论跨权重一致：0.55（旧默认）有害翻转 2.39%，
0.70 是 1.04% 且增益更高，0.35 直接转成 −1.07%。默认已改为 **0.65**。
λ 再往下走就是**语言模型压过字形证据、开始编字**。

## 泄漏防护

评测脚本先把每个测试页的金标窗口（前后各多挖 200 字）从本书语料里剔除
再训练，并打印挖掉了多少字（本次 36,290 字）；打印为 0 就是挖漏了，
后面的数字一概作废。

- 通用语料对测试页金标的 8-gram 重合率 **0.0**；
- 本书语料挖完之后仍有 **0.85%** 残余——《總目》里本来就有重复的提要
  套语，压不到 0，如实记着。

## 已知局限

见 `metadata.json`。最要紧的：**上下文取相邻列金标**（理想值，故增益是
上界）；候选只来自 rapidocr 一个来源；三册同属一部书，跨书泛化没测过；
页是分层抽样的，页型占比不等于全册占比。

## 重建

```bash
cd open-guji-cv
for B in book9 vol01 vol02; do
  PYTHONPATH=. python scripts/build_context_correction_dataset.py output/$B \
      --corpus corpus/zongmu_wuyingdian_reference.txt \
      --dataset ../open-guji-dataset --max-pages 60
done
PYTHONPATH=. python scripts/eval_context_correction.py \
    ../open-guji-dataset/context-correction \
    --general-corpus corpus/external/daizhige_zhaoling.txt \
    --book-corpus corpus/zongmu_wuyingdian_reference.txt \
    --sweep 0,0.25,0.5,0.75,0.9,1.0 --lam 0.65 --surface-pref --max-rival-freq 2
```

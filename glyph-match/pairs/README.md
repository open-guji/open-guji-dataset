# pairs —— 匹配判据的**阈值标定**集

## 为什么有这个集

隔壁 [triplets](../triplets) 只量**排序**（同字要比形近异字更匹配），可
判决用的是**绝对阈值**（cov ≥ same 闸）。2026-08-24 换 elastic 判据那一轮
把这个缺口暴露得很彻底：排序大幅变好（hard 0.079 → 0.684），库匹配的
same 档覆盖率却掉了三到四成。机理（软权对笔画密度敏感）是事后手工从
char-clustering 里刨出 42806 对才看清的——**那件事该有个正经数据集，而不是
每次手工重来。**

## 测什么

一对归一图块 → `same` / `diff`，**用来定操作点**。

金标定义（标注与评测共用；把「不算什么」也写出来）：

> `same` = 两个图块的金标 surface char **严格相同**；`diff` = 不同。
> - 异体字 / 通假**不算** same（严格按 surface char）——语义精度是另一
>   本账（见 `eval_db_match` 的「语义精度」）；
> - 图块质量**不影响标签**：degraded 的也照标，质量走 `tier` 分层报；
> - 两个实例任一金标有噪声，对标签就跟着有噪声（见 `label_noise`）。

## 主指标对着**危害**

库匹配判错一对的代价是**把错标写进库**，会沿簇批量扩散；判漏的代价只是
这个实例改走 OCR+上下文，慢一点。两类错误代价差着量级，所以不报单一
准确率，主输出是：

> **在 `precision ≥ 0.999` 下，闸能放行多少真同字对（recall），闸是多少。**

## 两条读数纪律

1. **precision 依赖同异字先验，三个来源绝不能混着报。** 它们的先验差着
   数量级，合起来的 precision 没有意义。headline 看 `knn` 层——那是生产
   真正会去验的对群。
2. **比值连分母一起读。** precision 从 1.0 掉到 0.998 可能不是退步，是
   放行的对多了。评测输出每个数都带分子分母。

## 对从哪来

| origin | 怎么抽 | 为什么要它 |
|---|---|---|
| `knn` | HOG top-10 册内近邻 + top-5 跨册近邻 | **生产真正会去验的对群**，操作点必须在它上面标 |
| `random` | 与特征无关的随机配对（同字 3000 / 异字 2000）| `knn` 由被测栈自己的第 3 层选出、**有偏**；随机层才是 recall 的无偏估计 |
| `near_form` | `NEVER_MATCH_FAMILIES` 逐族配对 | 人裁来源的硬负例，异字对里最危险的一批 |

`knn` 层是**故意**用被测算法选样本的——阈值就是要在这批对上生效。但它
确实有偏（HOG 认为像的对被过采样），所以 `random` 层必须一起报：
**两个数不一致本身就是信号**。

## 分层（必须分层报）

`ink_bucket`（笔画密度，取对中较高的一档）——这是本集的头号用途；
`tier`（任一侧 degraded 即算 degraded）；`book`（册内／跨册＝不同刻工）；
`origin`。

## 量法

```bash
cd open-guji-cv
PYTHONPATH=. python scripts/eval_match_pairs.py ../open-guji-dataset/glyph-match/pairs
PYTHONPATH=. python scripts/eval_match_pairs.py <集> --method coverage   # 旧判据对照
PYTHONPATH=. python scripts/eval_match_pairs.py <集> --dump s.npz        # 存分数
PYTHONPATH=. python scripts/eval_match_pairs.py <集> --from-dump s.npz   # 反复扫阈值（秒级）
```

打一遍分 71497 对约 4 分钟（elastic）；存了 `--dump` 之后再换阈值是秒级的。

### 历史：笔宽归一时代（见 `metadata.json` 的 `baseline_history`）

那一版 crops 是笔宽归一的输出，两个判据在同一批图上的对照结论仍成立：

- coverage 在对级上**达不到** `precision ≥ 0.999`（0.9973/2263）——它在
  `eval_db_match` 里过门靠的是 kNN 检索 + never-match 护栏 + best-of-k 兜底；
- elastic 同闸 precision 满分、recall 略高，硬约束下可用 recall 是它的 5.8 倍。

## 已知局限

- **`knn` 层由被测栈自己的第 3 层（HOG）选出**，对群有偏。这是故意的
  （阈值就在这批对上生效），但 recall 的无偏值要看 `random` 层。
- **标签噪声会翻倍传导**：对标签错 = 两个实例任一金标错。char-clustering
  的 align 层抽检 96 张 0 误标、95% 置信上界约 3%，对级上界约 6%。
  精度差 0.001 量级的比较要当心。
- **只有两册（vol01/vol02）**，都是同一套刻工传统。跨册层量到的是「同书
  不同册」，不是「不同书不同刻工」。
- `near_form` 只有 190 条：多数形近族的两个字不同时出现在这两册里。
- 图块冻结为**归一图**，所以本集测的是第 4 层判据；归一化本身的改动
  要用 [char-normalization](../../char-normalization)，且归一化一改，
  本集的 crops 就该重建。
- 单例：`random` 层的同字对在字类之间不是均匀的（先抽字类再抽两例），
  常见字被过采样。

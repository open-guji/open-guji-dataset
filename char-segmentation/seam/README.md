# char-segmentation / seam —— 切缝墨率（格线是不是切在字上）

## 这个分片在测什么

「上下接壤」这一族毛病——邻字的墨蹭进本格、本字的尾巴被留在隔壁——
根子都是同一件事：**两格之间那一刀切在了笔画上**。

这件事**不需要人工标注**就能量。把一列的墨横向投影铺开，格线所在那
一行的墨量，除以上下两格字身的墨峰：

```
切缝墨率 = 平滑列投影(格线 y) / max(min(上格峰, 下格峰), 0.35 × 本列峰中位)
```

- 分母取上下两格的**较小**峰：一刀要同时挨着两边的字才叫「切在字上」；
  只有一侧有字时，那是列端/空格，不该算进来。
- 再用本列峰中位兜底：稀疏邻格（一个「一」字）会让 min 掉到很小，
  比值就飞了。实测不兜底时 clean 格的比值最高能到 3.6。

比值 ≥ **0.7** 记作一条「重切缝」——这一刀基本贴着笔画走。

## 为什么不是人工标注分片

隔壁 [`instances`](../instances) 的人工标签挂在 `page:col:idx` 上，
**每次重切都会漂**（那份 README 自己写着「不能当作可自动重跑的切分
回归基准」）。实测拿它验切缝量法，AUC 只有 0.32——不是量法不行，是
标签早已不对应当前产物。所以这一族必须用**无监督**的量。

## ⚠ 它不能证明什么

这条闸量的**正是** `snap_bounds_to_gaps` 直接优化的目标。用它来证明
吸附/微挪本身有效，就是自考。它的用途只有一个：**守住**——以后任何
改动都不许让重切缝变多。

吸附本身的验证走三条独立路子：人眼 A/B（挪动的格线逐条看）、
`instances` 的重切金标（含住+盖墨）、`frame-strip` 的字保全。

## 跑分

```bash
cd open-guji-cv
PYTHONPATH=. python scripts/eval_seam.py ../open-guji-dataset/char-segmentation
```

页面范围 = `page-type` 金标里 `page_type == "body"` 的 294 页
（vol01 108 + vol02 186）。非正文版式（目录/职名/序跋）排版规矩不同，
按现行策略不进指标。

## 金标怎么更新

`--update` 把当前实测重新冻结。**只在确认是改进时用**，并在提交信息
里写清哪一项换来的下降。

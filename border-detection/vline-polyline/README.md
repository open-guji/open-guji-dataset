# 界行三段折线金标

`VLine` 的三段折线 `(x, k1, k2, k3)` + 折点 `y1/y2`，逐段人裁。
**线号从右到左、从 1 开始**，跟 `BorderDetectionResult.verticals` 的顺序一致
（`verticals[0]` 最右）。再生：open-guji-cv 的
`scripts/export_vline_polyline_gold.py`；看图：`scripts/draw_polyline_overlay.py`。

## 第一轮（2026-09-02，vol01/11、119、151，共 90 段）

用户看逐列叠图（红=拟合前直线、绿=三段折线、黄点=折点）逐段裁决，
**approved 83/90**。每段附 `w80`（装下 80% 墨的最窄 x 跨度，越小越贴真墨）
和 `peak`（投影峰高）。

| 页 | approved | 用户点名不对的 |
|---|---|---|
| vol01/151 | 30/30 | 无——全部完美 |
| vol01/11 | 27/30 | L1 三段全部（已人工定位，见下）|
| vol01/119 | 26/30 | L1 段2/3（模型局限）、L3 段3、L4 段1（已修）|

被拒那几段，w80 12~22 / 峰 0.40~0.47，而 approved 的段是 w80 4~9 / 峰 0.78~1.00
——**人裁跟指标是一致的**，可以放心拿 `w80` 当自动判据。**但要排除 `w80` 为
`null` 的线**（墨太少、指标量不出来，位置靠人定，见下面 vol01/11 L1）。

## 被拒 7 段：两种病，一条人工定位，一条判为模型局限

**病一：折点搜索半径不够**（vol01/119 L3 段3、L4 段1）。真墨离直线中位 23px
（到 33）和 18.5px（到 55），而 `KNOT_SEARCH` 原来是 24，折点够不着。
扫 24/40/60 后定 40：这两段 w80 19→15、22→13，离真墨 24→8px、28→7px；
60 再无收益，对照页 vol01/151、11、24、vol02/95 一个数都没变。**已修**。

**病二：窗口里压着两条线状墨带**（vol01/11 L1、vol01/119 L1，都是最右那条框线）。
内框细线 + 外框粗条一起落进 ±40px 窗口，合起来墨宽中位 17~21px，被
`BEND_INK_W_MAX=9` 全剔掉，有效行只剩 83/1185 和 46/1197，低于 `BEND_MIN_ROWS`
就退回直线、根本没拟合。补救是让拟合失败的线**借同页已拟合线的折点位移中位数**
（同一页的线是一起弯的），vol01/119 L1 段3 靠这个从离真墨 20px 修到 1px。
剩下两条各有归宿：

### vol01/11 L1 —— 人工定位，`gold_origin: "human"`

算法整条找错了位置：它离 L2 只有 155px，而该页其余列距中位 183px（差 28px），
绿线处根本没有细框线。用户实拖四端点位移 **−20 / 0 / +20 / +20**，
存在 `manual.shift_px`，`gold` 已换成人工值（`polyline` 保留算法值作对照）。

⚠️ 这条线**很虚**——`gutter_projection` 对算法线和人工金标线**都**返回"有效行
不足"，所以它三段的 `w80`/`peak` 都是 `null`。**那不是"金标不可信"，是这条线
的墨少到指标量不出来**，位置只能靠人定。拿 `w80` 做自动评测时要把这类线排除，
别当成回归失败。

### vol01/119 L1 —— 判为模型局限，按现状收为金标

用户裁定：真线是「**第一段直、第二段弯、第三段直**」。三段模型的每一段都是
直线，表达不了中间那段的弯；**除非增加段数，否则调不动**。用户认为不必增段，
按现状收。记在 `lines[0].limitation`，`segments[1..2].approved=false` 保留——
标的是"算法这两段不对"，同时承认"三段模型下没有更好的答案"。

**这是三段模型已知的表达上限**：能吃住整条平滑弯曲（151、47、95 型），吃不住
「直—弯—直」这种段内还带曲率的形状。要覆盖它得加段数（五段）或换曲线模型，
不是调参能解决的。

# char-segmentation / text-band —— 文字带窗口够不够装下一整列

## 这个分片在测什么

列的纵向窗口来自 phase2 `inner_frame` 的上下界。版面检测把**正文中间的
某条横线**当成上框或下框时，窗口能塌到只剩三分之一页——窗外的字全部被
判空、**静默丢掉**，产物里既不报错也不留痕。

实测（2026-08-25 首次量到）两册 **21 张正文页**中招：

| 页 | 窗口比 | 切出字格（正文页中位 168）|
|---|---|---|
| vol02/97 | 0.322 | 47 |
| vol02/153 | 0.352 | 54 |
| vol02/77 | 0.302 | 71 |
| vol02/137 | 0.463 | 81 |
| vol01/70 | 0.483 | 101 |
| …共 21 页 | | 按中位估算丢 ≈1276 格 |

## 量法：不看像素，看模型

文字带高是**书级刚性常量**：

```
应有窗口高 = 每列字数 × 书级格高（全书 cell_h 中位）
窗口比 = (inner_frame.bottom − inner_frame.top) / 应有窗口高
```

比值 < **0.90** 记一张「窗口偏短」页。这跟 [`page-crop`](../page-crop)
是同一个路子——**把判据搬到图块之外**，拿网格模型跟页面几何直接比，
不设任何像素阈值，因此不受污渍、墨色、扫描亮度影响。

被 `Pass 2a4`（整页放开重扫）救过的页在产物里带 `grid.band_widened`，
不再计入塌陷数——它们的 `inner_frame` 依旧是错的，但窗口已经不用它了。

## 回归口径

- 不许出现**新的**塌陷页；
- 已塌的不许塌得更狠（比值不许再降 0.01）；
- **正文字格总数不许掉超过 2%**——这是防「为了让塌陷数好看而少切字」的
  反向护栏。

```bash
cd open-guji-cv
PYTHONPATH=. python scripts/eval_text_band.py ../open-guji-dataset/char-segmentation
```

- `vol01/88` 是**救援被正确撤回**。它原先带 `band_widened`（因此不计入

  越界 84px——救的是幻影。新增的「出界格判空」（`OFFPAGE_KEEP`）把这些
  格判掉之后，盖墨判据不再采纳该页的放开，`band_widened` 消失，于是它
  按本来面目露出来：phase2 的 `inner_frame` 在这一页确实偏短 0.898。
  现在越界 84px→42px、页外格 9→0，页底实图核对过、其下没有真字。
  **窗口偏短是上游 phase2 的事实，不是切分层新造的缺陷。**

这条记录也是个通用提醒：`band_widened` 让一页**跳过**本闸，所以任何改
动只要动了 Pass 2a4 的采纳面，都会让一批页在本闸上「凭空出现或消失」。
读本闸的差异时，先查 `band_widened` 有没有翻转，再谈塌陷。

## 已知局限

- 只覆盖 `page-type` 金标里的 **body** 页（294 张）。非正文版式各有各的
  排版规矩，按当前策略不进指标。
- 判据用的是**书级格高中位**，所以它假定全书同版式。换书要重新确认这个
  前提成不成立。
- 它只查**窗口够不够长**，不查窗口**位置对不对**。位置错但长度够的页
  （首末字被裁掉一行那种）要靠 recrop / frame-strip 那两条闸。

# char-clustering —— 保守聚类 purity

## 测什么

**一册里的字块按字形并簇，同一个字尽量进同一簇，但绝不允许不同字混进一簇。**

对应命令 `guji-cv cluster <book>`。取向是**宁可碎，不可脏**——脏簇会把错标
沿整簇批量扩散，碎簇只是多花人工审查成本。所以 `purity` 是硬约束
（≥ 0.999），`fragmentation` 只在 purity 达标之后才有意义。

这不是抽象的担心：本数据集的人工层就是被这样污染的。glyph_store 里那 94 个
「人工」标签全是 `label_status: propagated`——人工确认了**一个簇是什么字**，
标签再传播给全部成员，簇里混进来的字就跟着背上了错标。逐张复核 94/94，
**11 个对不上（11.7%）**。脏簇的代价，这就是实测值。

## tier 分层：干净 / 退化（2026-08 起）

上游切分做不到完美，图块分两类，算法目标分两档，评测分开报：

| tier | 定义 | 对聚类的要求 |
|---|---|---|
| `clean` | 字完整、无外来残留 | purity 硬约束里的硬约束；碎片率优化主要看这层 |
| `degraded` | 有残留或本字被切 | **能不崩**：不并错就行，单例流向审查队列是正确行为 |

每个实例在**原始图块**上跑 `crop_quality.assess_crop` 分级（判据与校准见
[char-normalization/README](../char-normalization/README.md)——分级不能在
冻结的归一图上做，那已经过了归一化自己的清理）。分布：001 分片 clean 95%、
002 分片 89%、人工层 54%（本来就是从问题簇里来的）。

## 金标怎么来的

### align 层：整理本对齐

页转写（`phase6_labels/ranked.json`）只是**对齐载体**，字标签一律取自
[整理本语料](https://github.com/open-guji/open-guji-cv/blob/main/corpus/)：

1. 页内 8-gram 投票把这一页锚到语料的正确位置；
2. `SequenceMatcher` 在窗口内逐字对齐；
3. `equal` 段（转写与语料一致）与**等长 `replace` 段**（转写错了、金标以
   语料为准）都收——后者恰恰是最有价值的那批，脏簇就藏在那里。
   `insert`/`delete` 段整段丢弃：那里的实例与语料字对不上号。

两道闸门，缺一不可：

- **页结构一致性**：`ranked.json` 与当前 `index.jsonl` 的全部 `(列, 格序号)`
  必须逐一相同。`page:col:idx` 是当前切分产物的编号，上游一改就指向别的
  格子——实测 vol01 110 个正文页里只有 58 页结构还对得上（转写产自更早
  一次 phase4），不校验就会把标签系统性错位一格。
- **三条清洗**：非汉字（语料换行会被对成一个字）；`replace` 且
  `ink_ratio < 0.05`（近空格位）；`replace` 且带 `frame_bars`（版框横线格位）。
  `equal` 位不套后两条——转写与语料两边都指向同一个字，证据强得多。

清洗前后各抽检一批（每批 32 张，把字块铺成蒙太奇逐个核对）：

| | 清洗前 | 清洗后 |
|---|---|---|
| vol01 `equal` | 32/32 对 | 32/32 对 |
| vol01 `replace` | 30/32（2 个是空格位）| 32/32 对 |
| vol02 混合 | 31/32（1 个是纯版框横线）| 32/32 对 |

清洗后 96 张抽检 0 误标，误标率 95% 置信上界约 3%。

### human 层：逐张复核过的人工标签

glyph_store 的 94 个 propagated 标签逐张目视，**8 个改标、3 个丢弃**：

- 改标的留在集里——它们正是「当初那个簇混进了别的字」的证据
  （例：两个实例被确认成 `圖`，实际是 `守`）；
- 丢弃的是判不准或压根不是单字的（一横与界行分不开 / 氵旁字沿治两可 /
  四个残字拼在一格）。

复核表在
[`build_clustering_dataset.py`](https://github.com/open-guji/open-guji-cv/blob/main/scripts/build_clustering_dataset.py)
的 `RELABEL` / `DROP`，每条带依据；改标注只改那张表。

## 难例对：线索必须与判据不同

用配准 F1 挑难例、再拿 F1 去判，是自证。所以：

| 类型 | 抽样线索 | 与判据的关系 |
|---|---|---|
| `diff` | **转写混淆表**（OCR 候选 + LM 排序把 A 认成 B 的那些字对）| OCR/LM，与配准 F1 无关 |
| `same` | **同字实例的墨色两极**（`ink_ratio`，extractor 的量）| 切分阶段的量，与聚类无关 |
| `same`（人工层）| 人工 `confirm_same` 事件 | 人工判断 |

## 基线（2026-08-23，pipeline `23ee9a5`，θ_high=0.80 / hog）

| 分片 | purity | 多实例簇 purity | 簇数/字类 = 碎片率 | 单例率 | `diff` 对 | `same` 对 |
|---|---|---|---|---|---|---|
| 001-vol01-body | **0.99900** (2998/3001) | 0.99148 (349/352) | 2790/975 = 2.86 | 95.0% | 39/39 | 0/40 |
| 002-vol02-body | **0.99903** (3102/3105) | 0.99438 (531/534) | 2758/743 = 3.71 | 93.2% | 40/40 | 0/40 |
| 003-book9all-human | 1.00000 (91/91) | 1.00000 (26/26) | 77/24 = 3.21 | 84.4% | — | 9/60 |

按 tier 分层（同一次聚类，换一副眼镜看）：

| 分片 | clean purity | clean 碎片率 | degraded purity | degraded 碎片率 |
|---|---|---|---|---|
| 001-vol01-body | 0.99895 (2848/2851) | 2.77 | 1.00000 (150/150) | 1.24 |
| 002-vol02-body | 0.99892 (2767/2770) | 3.48 | 1.00000 (335/335) | 1.55 |
| 003-book9all-human | 1.00000 (49/49) | 2.33 | 1.00000 (42/42) | 1.81 |

**读法**：退化层 purity=1.0 且几乎全单例——保守聚类对脏图块的行为正是
「不并、流向审查队列」，这是设计要的「不崩」，不是成绩。仅存的 3 处混簇
**全在 clean 层**且全是形近字——干净数据上的形近字才是真正的敌人；
碎片率的优化空间也集中在 clean 层（2.77/3.48）。

**读法**：

- purity 达标，但**单例率 93~95%**——聚类几乎没有并簇。聚类的收益本来是
  「137 个实例的簇只认 3~5 个代表」，现在等于没拿到。
- 所以主看 `多实例簇 purity`（0.991/0.994）：把单例那份白送的 1.0 摘掉之后，
  脏度是这个数。
- 脏簇全是形近字：`人/入`、`大/太`、`未/末`、`面/而`、`夬/夫`。与设计文档
  18.4 的结论一致——**形近字混簇不是调阈值能解决的**。
- `same` 难例对 0/40：墨色两极的同字对一对都没并上。着墨浓淡是刻本同字
  差异的第一大来源，笔宽归一（3a）现在扛不住它。这是 3a 的待办，不是 3b 的。

### θ_high 扫描：0.80 是唯一守得住硬约束的档

| θ | vol01 purity | vol01 碎片率 | vol02 purity | vol02 碎片率 |
|---|---|---|---|---|
| 0.68 | 0.98534 | 1.79 | 0.98567 | 1.96 |
| 0.72 | 0.99500 | 2.17 | 0.99414 | 2.43 |
| 0.74 | 0.99733 | 2.39 | 0.99739 | 2.74 |
| 0.76 | 0.99800 | 2.55 | 0.99837 | 3.08 |
| 0.78 | 0.99833 | 2.72 | 0.99870 | 3.40 |
| **0.80** | **0.99900** | 2.86 | **0.99903** | 3.71 |

再低一档就破 0.999。**碎片率要降，得从别处来**（归一化把同字拉近，或者
verify 换更能容忍墨色的判据），不是把阈值调松。`diff` 难例对在**所有档位
都是 100%**——形近字对不是被阈值挡住的，是配准 F1 本来就把它们分开
（异字对 F1 中位 0.40，最高不到 0.80）。

## 怎么跑

```bash
cd open-guji-cv
python scripts/eval_clustering.py ../open-guji-dataset/char-clustering
# 端到端（给管线跑全书的产物打分，要求 pipeline_version 一致）
python scripts/eval_clustering.py ../open-guji-dataset/char-clustering \
    --shard 001-vol01-body --clusters output/vol01/phase5_clusters/clusters.json
```

重建数据集：

```bash
python scripts/build_clustering_dataset.py --dataset ../open-guji-dataset/char-clustering
```

## known_limitation

1. **只覆盖能锚定的页**。vol01 110 个正文页里 58 页结构一致、49 页锚定成功；
   vol02 186 页里 65/35。锚不上的页多是转写太差或整理本未收——所以这批
   实例**系统性地偏向「切分与转写都还行」的页**，不是全书真实分布。
2. **29 条人工 `impure`（`diff`）对全部丢失**：反馈事件只导出了 `confirm`
   的图块，`impure` 那些实例既没有冻结图、编号又指向早已重跑过的产物。
   人工层现在**一条硬负例都没有**，`diff` 判定只由 align 层的混淆对撑着。
   给审查导出流程的待办：impure 对的两端也要落图。
3. **人工层只有 91 个实例、24 个字类**，字类少则冲突概率天然低，它的
   purity=1.0 不能单独当结论用；它的价值在于**标签干净**，是 align 层
   噪声底噪的参照。
4. **align 的 `equal` 段不是完全独立的证据**。转写经过 LM 上下文修正，
   LM 语料与对齐参考同源时，模型可能从上下文「填对」一个图像上根本没有的
   字——实测抓到 1 例（纯版框横线格位被转写认成「一」，语料那位置恰好也是
   「一」，两边一致就混过了 `equal`）。清洗规则只对 `replace` 生效，
   这类漏网留在集里。
5. **每分片 3000 实例是抽样**（vol01 可标 7947、vol02 5412），按整页随机抽，
   种子固定。要更大的集直接调 `--max-instances` 重建。
6. **tier 是机器分级、未逐个目视**（6000+ 实例看不过来）。判据对 62 个人工
   标签的实测：缺陷检出 5/7、clean 误报 2/55——clean 层里混着少量漏网的
   退化实例（校准集缺陷率 11% 时约漏 3%），分层数字要带着这个噪声读。
7. **本集冻结在 P0 修复之前的切分上**：图块比当前管线的产物更脏
   （vol02 无标记率当时 44.5%、现在 68.2%）。绝对数字与新切分不可比；
   迁移前置条件见上文「冻结」一节。端到端模式（--clusters）对新产物
   已不可用——实例编号全漂了。

# side-rule —— 侧边界行残余剥离

## 这个分片量什么

图块**左右缘**吃进来的竖线（界行 / 版框）有没有被剥干净，以及剥的时候
有没有误伤字自己的竖笔。

来源是 2026-08-25 用户第 7 轮实审的一句话：

> 标完 有一个自检太多了 我就没消除 还是有很多侧面边框误入
> 然后有一页左边小注 被竖着切断

那一批 18 页（vol01 4/18/53/70/84/142，vol02
7/9/29/51/52/75/92/105/115/138/144/171，共 2880 个实例）里用户判「切错」
的 52 格，一半是这一类。

## 为什么会漏进来

图块条带按切分给出的 `cell_left_x`/`cell_right_x` 裁，那条边是「从文字带
往外扩、扩到撞上竖线结构为止」。界行磨损断裂时那道墙检不出来，条带就一路
扩到列格名义边界，把界行整条圈进图块——实测 vol02/115、vol02/171 是**整列
整列**地在图块右缘留一条竖线。

## 标注怎么设计

不逐格人工画框，而是**按判据挖样本、用人工判错的格做正确性证据**：

- `side_rule: true`（正样本）——图块里有一条**中心落在文字带之外**的细高
  连通体。这类样本 25 条。判中心不判整条：最外一列挨着的版框线常常正好
  压在文字带边上（vol02/171 col1 的框线 1653~1660、带边 1653.7），按
  「整条出带」判会把它们全数漏掉。
- `side_rule: false`（负样本）——细高连通体的中心落在文字带**之内**。那是
  字自己的竖笔（忄的左竖、阝、川、而 的边竖），一根都不许剥。240 条。
- `main_ink`：建集时产物里最大连通体的墨量，作字身保全基线。
- `keep_ink`：负样本那些带内竖笔的墨量之和，用来验证它们还在。

「出不出文字带」这条线是人工标注验证过的：本批 71 个「细高贴边」候选里，
完全落在文字带外的 33 个有 28 个落在用户判错的格、**0 个落在用户判对的
格**；带内的 34 个里有 10 个是别的毛病，还有 1 个正是「訓」的川字最右竖
——只按形状剥必砍字。

## 指标（`scripts/eval_side_rule.py`）

| 指标 | 口径 | 目标 |
|---|---|---|
| 残余率 | 正样本里图块中仍有「出文字带的细高连通体」的比例 | 0 |
| 误剥率 | 负样本里带内竖笔墨量少于基线的比例 | 红线 0 |
| 字保全 | 全体样本里字身墨量 ≥ 基线的比例 | 红线 100% |

落地当轮实测：残余率 **25/25 → 2/25**（剩两条是有意的保守档：vol02/138
的框线断段确实紧贴阝的竖笔，12px 之内），误剥 **1/240**（基线错位，
该格的窗口被同轮的宽缝补齐改过），字保全 **262/262**。判据推导与三次
踩坑见 open-guji-cv 的 `.claude/doc/char_clustering_design.md`
「侧边界行残余剥离」一节。

## 重建

```
PYTHONPATH=. python scripts/build_side_rule_shard.py \
  --pages vol01:4,18,53,70,84,142 \
          vol02:7,9,29,51,52,75,92,105,115,138,144,171 \
  --out <dataset>/char-segmentation/side-rule
```

注意：重建会**按当前产物**重挖样本。剥离生效之后正样本就消失了，所以
`expected.json` 必须在剥离**落地之前**的产物上建，不要拿修好之后的产物
覆盖它。判据改口径要重建时，从 git 里取落地前那一版产物：

```
mkdir -p /tmp/prefix && cd /tmp/prefix && \
  git --git-dir=<repo>/.git archive <落地前的 commit> \
    output/vol0{1,2}/phase4_chars/index.jsonl output/vol0{1,2}/phase3_char_grid \
    output/vol01/phase4_chars/patches/{4,18,53,70,84,142} \
    output/vol02/phase4_chars/patches/{7,9,29,51,52,75,92,105,115,138,144,171} \
  | tar x
```

然后在 `/tmp/prefix` 里跑上面的建集命令（脚本按相对路径 `output/` 找产物）。

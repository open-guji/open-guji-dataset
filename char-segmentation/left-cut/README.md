# left-cut：左缘穿边金标（right-cut 的镜像）

撇尖/横笔左端穿过 `cell_left_x` 裁切边被切掉（右缘 r10 用户反馈
「有的整列从右边被剪切」的镜像病灶）。全书机扫 58 列 114 点。

## 判据（v2 定版）

连通体从裁切左边**外** ≥4px 连进格内 ≥6px，且：

- 高 ≤30 —— 排界行竖线；
- 面积 ≥25 —— 排噪点；
- **宽 ≤45 且不贴探测窗左缘** —— 排横向栏线/中缝线（v1 废案：无此
  两条时扫出 324 点，抽样近半是细着穿边的栏线，另一头在窗外）；
- **离版框带内缘（`frame_band_inner`）>12px** —— 排上/下框线磨损断
  段（v2 之前的废案：无此条时评测 14 个「失败」逐个目验全是压在下
  框线上的短段，y 集中在 2320~2483）。

`extent` = 穿边组件左端 x（页坐标，去错切帧）。

## 回归口径

现场重跑 `extract_page`（不读产物），穿边点所在格的图块外接框左缘
须 ≤ extent+2。门：仍被剪 ≤10%（疑难：噪点场里的假穿边、贴着 12px
框带线外侧的边界个案）。评测：
`PYTHONPATH=. python scripts/eval_left_cut.py <数据集目录>`（open-guji-cv）。

## 救援链上的四个对冲点（修复记录，2026-08-26）

左缘救援（`widen_left_for_crossing`）外扩后，救回的笔尖要活着走完
整条流水线，先后修了四处「在条带边缘取证/涂抹」的下游步骤：

1. 曲线掩膜左界随外扩放宽（镜像右缘老修）；
2. `mask_frame_bars_outside` 左侧取证窗止步于外扩前裁切边（镜像
   vol01/34「類」红线修）；
3. `_assign_column` 边缘噪点门槛：救援带穿边碎片按文字区门槛保；
4. `carve_end_edge`：字身外实体墨块（≥60px、离被切端 ≥15px）并入
   保护圈——「南」顶横断墨的左端（111px）曾被列首曲线切边绕过抹掉。

## 退役记录 & 一条结构性告诫

**2026-08-26 退役 1 点**：`vol02/184:8 y=2356 extent=217`
（→ `retired_rule_residue.json`）。它标的是**界行残段**不是字墨，连通体实测：
该块 x217~232、面积 227、高 32px，与「畫」字身（x269~375、面积 5482）
**不连通**，整块落在列左界 258 之外 26px。

⚠ **这条闸会把「把界行渣吸进格子」记成救回成功。** 判据是「格的紧裁框
左界 ≤ 穿边墨的左端」，而紧裁框是**跟着格内容走的**：格里混进列外的渣，
框就往左跑，于是渣自己把自己「救回」了。造这条金标时 vol02/184:8 的框
左界是 216（已被那块渣拉过去），所以当时算通过；骑线复切把格子切干净、
框回到 267 之后，同一点反而被读成回归。

**推论**：界行剥离/切分变干净时，这条闸会给出反向信号。读它的差异必须
先问一句「框往右跑是因为字被剪了，还是因为渣被清了」——用连通体查
「被剪的墨与字身连不连通」，连通才是真被剪。

金标锚点本身也该修：`cell_left_x` 记的是造标时的紧裁框（会动），应改锚到
**列的裁切边**（不动）。未做，记为待办。

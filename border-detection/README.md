# border-detection —— Step1（边框探测）人工核校金标

## 这个子集在测什么

切分管线重定义的 Step1（见 `open-guji-cv/.claude/doc/segmentation_v2_pipeline.md`）：
从原始扫描图上找出版框（上下内外边框）和界行（列间分隔线），倾斜、
模糊/磨损都要处理；有抬头列的页面额外定位抬头框的内外上边框。这个子集
是这一步的**几何金标**——人工核校过的线位置（坐标+斜率），不是"探测对
不对"这种粗判，是可以直接拿来算任意新算法"切在哪"跟"该切在哪"差多少
像素/度的量。

在这个子集之前，切分链路里没有任何一份数据集直接测边框/界行坐标本身——
`open-guji-cv` 那边的 `text-band`、`page-crop` 等测的都是边框探测出错之后
**下游的症状**（窗口太小丢字、裁切吃掉整列），不是边框位置的金标；
抬头框的坐标此前完全没有任何人工核校数据。

## 图源：最原始扫描，不用任何预处理产物

样本里的 `source_image` 都是 `rebuild_src/<book>/<page>.tif`——**未经过
s3 裁剪、未做 s4 直线增强**。理由：s4 直线增强能把边框位置挪动最多
96.6px（`open-guji-cv/.claude/doc/peak_line_search.md` 记录过），这个量级
足以让边框探测本身的结果失真；Step1 的算法（半高宽匹配度 + 位置角度
联合搜索）设计上就是给未矫正的原始图用的，不需要预处理帮忙去斜/裁剪。

## 坐标系：右上角原点，从右到左，从1开始

跟 `open-guji-cv` 旧管线（`phase2_layout`/`phase3_char_grid`）的坐标系
不一样，这是切分管线重定义时明确要改的：

- 原点在页面**右上角**（旧管线左上角）。
- x 向左递增，y 向下递增。
- 列号从右到左、从 1 开始——对齐古籍阅读顺序。

每个样本 JSON 的 `coord_space` 字段完整写了这个约定，具体公式见
`open_guji_cv/utils/border_geometry.py` 的 `HLine`/`VLine` 类。

## 版式结构：内外边框 + 抬头框

版框不是一条线，是有内外两层的：

- **上下版框**：`top_inner`/`bottom_inner` 是贯穿全页的内层线
  （`{y_at_right, slope}`）；`top_outer_offset`/`bottom_outer_offset` 是
  外层线相对内层线的偏移量（新坐标系里 y 方向的差值，**斜率锁定跟内层
  一致**——物理上是同一块印版/同一张纸的两条平行边，不需要单独的角度
  自由度）。
- **左右边框**：`verticals_inner` 是 N+1 条内边框/界行（N=列数），
  从右到左排列（`[0]`=第1列外边框/最右）。外边框**只在纸边那一侧存在**
  ——这批书是筒子页对折装订，偶数页纸边在左、奇数页纸边在右，版心/
  装订那一侧没有独立外边框（被切/装订吃掉，不是没探测到）。`v_outer_side`
  标了是哪一侧，`v_outer_offset` 是外边框相对该侧最外一条内边框的偏移量
  （新坐标系 x 方向，同样斜率锁定）。
- **抬头框**：`head_raise` 列表，每条 `{col, inner_y, outer_y, estimated}`——
  某一抬头列自己的内外上边框，是局部量（只对这一列有意义，不贯穿整页）。
  `col` 是新坐标系列号（从右到左、从1开始）。另外三个字段
  `handle_x`/`snapped_gutter`/`snap_dx` 记录这条记录是从标注页上哪个手柄、
  吸附到哪条界行来的，便于追溯，不是几何量本身。

### 抬头框的标注语义（重要，导出时必须照这个来）

**一个手柄 = "这一列有抬头"，手柄对齐到该列的右边界那条界行**（用户
2026-08-31 确认）。所以从标注页导出列号时：**把手柄 x 吸附到最近的界行，
再归给该界行左边（屏幕）那一列**。

⚠️ 早期导出脚本用的是 `lo <= 手柄x <= hi` 区间包含判归属——因为手柄就
压在界行上（实测 12 个手柄里绝大多数离边界只有 0.1~8.4px），落在边界哪
一侧完全由浮点毫厘决定，**等于抛硬币**，已经导致 33/47/49/51 四页列号
判错，并判出了物理上不可能的重复（一列出现两个抬头框）。2026-08-31 已
按新规则重导，标注页也改成拖动时自动吸附界行并直接显示/存下列号，不再
让导出脚本事后猜。

**新旧规则在"手柄标在列中心"的老习惯下结果一致**（vol01/32 就是这么标
的，最近界行仍是该列右边界），所以只有手柄越过右边界几个像素那几例被
纠正。

## 已知局限：vol01/32 的抬头框是推测值，不是观测值

vol01/32 有 5 个抬头列，但**抬头框的上边框在这一页的扫描里被物理装订/
裁切吃掉了**——不是"线弱看不清楚"，是那个位置根本没有被扫描图覆盖到，
标注时纯靠推测大致该在哪。这 5 条记录的 `estimated` 字段都是 `true`，
**不能跟其他能直接观测到线的记录同等确信度使用**——校验新算法时应该
分开报告（`estimated=false` 的记录才是真正的位置精度基准，`estimated=true`
的只能用来判断"数量级对不对"）。

### head_raise 已按真墨重拟（2026-08-31）

**坐标口径（用户定）**：`inner_y` = **线心**，`outer_y` = **外延**（外框
常是一条 15~23px 的粗条，取朝外那一侧的边缘；上边框朝外就是 y 小的一侧）。
墨量**只在该列的窄窗口里**算（两侧各内缩 12% 避开界行/墙线）——抬头框只
存在于这一列，按整行算会被邻列的墨污染。

**改了什么**：
- `inner_y` 13 例全部重拟，移动 −3.4 ~ −10.7px。原值**全部同号**偏低：
  金标位置实测墨占比只有 0.000~0.096（**根本不在墨上**），上方 4~11px 才是
  那条墨占比 0.33~0.96 的细锐线。
- `outer_y` 11 例重拟为外延，移动 −9.7 ~ +2.9px（绝对均值 4.0px）。原值
  多数已经落在粗条靠外的位置（条内 2~41% 处），这次只是把口径定死。
- vol01/32 那 5 例（`estimated=true`、线被物理裁掉）两个坐标都无墨可测，
  原样保留。

**新字段**：`inner_observed` / `outer_observed` 分别记这两个坐标**是不是量
出来的**，`estimated = not (inner_observed and outer_observed)`（跟
`border_geometry.HeadRaiseBorder.estimated` 语义对齐）。现状 18 条记录里
inner 观测 13 例、outer 观测 **11** 例——**vol01/51 的 c2/c8 外框在扫描里
根本没印上**（`outer_y` 处墨占比 0.000），已标 `outer_observed=false` /
`estimated=true`；c1 的外框是有的，只是很浅（峰值 0.35），保持观测。

**量法要点（踩过的坑都在这）**：
- 墨占比门槛必须是**绝对值**（内框 0.25 / 外框 0.30），**不能用"峰值的
  一半"**——外框常常是满墨(1.0)，相对门槛会被抬到 0.5，而真内框只有
  0.33~0.47，会被整批杀掉（vol01/47 四例全中）。
- 线心 = 连通段内"峰值半高以上"那截的加权质心；外延 = 墨占比跨过该段峰值
  一半的那个点（朝外一侧），线性插值取亚像素。
- 拦混淆：要求 `inner-outer` 间距落在 25~52px，把**外框本身**（间距太小）
  和**下面第一个字的横画**（间距太大，实测在 y≈350 一带）两头都排掉；
  合规候选里取**最靠里**（y 最大）那条，即使比较浅。

**独立验证**：重拟后，生产 `detect_head_raise()` 的误差 **inner 6.9→0.6px、
outer 3.3→0.4px**（最大 1.2px）。两套完全不同的方法（生产用半高宽匹配度
找峰，重拟用列内线心/外延）吻合到亚像素——说明探测器一直就找对了，原来
那几个 px 全是标注口径的差。（`detect_head_raise()` 原本返回粗条内的峰值
位置，这次一并改成同样的外延口径，否则会一直带 +2~4px 的系统偏差。）

**内外间距的一致性**（用户判据，已验证）：手标的页级 offset 四处都聚在
36~40px（上 36.3±6.2 / 下 38.2±5.1 / 侧 38.4±4.0）。抬头框按新口径量
（外延 → 内框线心）是 37.0 ± 5.7px；把两种形态拆开更干净——**9 例粗条
（宽 18~23px）是 39.5 ± 1.8px**，2 例细线外框（vol01/49 c6 宽 4px、
51 c1 宽 7px）是 24.1 / 27.1（细线的外延≈线心，自然短一截）。粗条那组的
39.5px 正好落在页级 offset 的区间里。

**字段**：`head_raise` = 重拟值，`head_raise_manual` = 人工原值留档，
`head_raise_refit.lines` = 逐条记录（含每个坐标处的墨占比、粗条范围、
移动量、重拟前后的间距）。重跑：
`python scripts/refit_border_head_raise.py [--apply]`（幂等，始终以
`head_raise_manual` 为基线）。

样本量还是不大，尤其抬头框只有 26/32/33/47/49/51 六页共 18 例（32的
5例还是推测值），复杂多列抬头(47/51型)目前只有2页——`detect_head_raise()`
的形态常数全是从这 13 个可观测样本上量出来的，换一种版式的书之前必须
先扩样本验证。另外抬头框的 `inner_y` 有 −4~−11px 的系统性标注偏差
（13 例全部同号，标注手柄拖到了线的下缘而不是线心），补标时一并规范掉。

## 样本怎么造的

1. `open_guji_cv/utils/peak_line_search.py` 在原始扫描上跑
   `find_vertical_lines`(expected_count=10) + `find_horizontal_border`
   (top/bottom)，得到内边框/界行的自动探测种子。
2. 生成交互标注 artifact（`claude.use('artifact')` 自存），种子按标准
   像素坐标存成"每条线上两个点"，方便拖拽核校；外边框和抬头框没有自动
   探测，种子是粗猜的起点，靠人工从零标定/大幅修正。
3. 人工拖拽核校：10 条竖直内边框/界行、上下 2 条水平内边框、上下各 1 条
   外边框偏移量、纸边侧 1 条竖直外边框偏移量、抬头页的抬头框（外/内
   上边框 y 值）。
4. 读回 artifact 状态，用 `border_geometry.py` 的 `HLine.from_endpoints`/
   `VLine.from_endpoints`（接受线上任意两点，不要求落在图像边缘）转成
   新坐标系，写入 `samples/<book>_<page>.json`。

生成脚本（未入库，在 `open-guji-cv` 会话临时目录）：
`gen_border_gold_seed.py`（种子）→ `build_border_gold_tool.py`（标注页）
→ `export_border_gold.py`（导出金标）。

### 上下内框：那 3 条不是脱靶，是磨得极淡（2026-09-01 复核，结案）

`vol01/137`、`/138`、`/141` 的 `bottom_inner` 曾被判为「整条画在白纸上」。
**复核结论：三页都印上了，只是磨得极淡，金标是对的**，不用改。

**先前判错的原因是门槛用了绝对值。** 用 0.20 这种绝对墨门槛判「有没有线」，
对糊页太粗暴。换两条判据：

1. **相对本底的局部峰**。本底（内框与外条之间那段白）实测就是 0.000，所以
   金标处 0.02~0.10 的墨已经是本底的 8~39 倍。清楚页 250~450 倍、「淡但明确」
   的 47/51/142/49 是 105~180 倍——**是一条连续的衰减谱，不是有无之分**。
2. **空间相干性**（真线 vs 噪点）。真版框线的墨沿 x 连成长横条，噪点是散点。
   量「覆盖率 + 最长连段」，并跟同页确定空白的对照行比：

   | 页 | 金标行 覆盖 / 最长连段 | 对照行 覆盖 / 最长连段 |
   |---|---|---|
   | 24（清楚）| 0.719 / 188px | 0.002 / 2px |
   | 47（淡但明确）| 0.257 / 55px | 0.000 / 0px |
   | 138 | 0.095 / 37px | 0.009 / 4px |
   | 137 | 0.027 / 25px | 0.000 / 0px |
   | 141 | 0.017 / 17px | 0.029 / 47px |

   137/138 在金标处都有远超对照行的结构，是真线。141 两边都只剩个位数碎片，
   下内框基本磨没了——但**算法在那页落在外框粗条上**（金标下方 28px 正是粗条
   近沿），比金标错得多。

体检脚本 `scripts/report_border_hlines_offtarget.py` 的绝对门槛口径同样偏严，
它报的「整条脱靶」应读作「这条边墨极少，值得看一眼」，不是「标错了」。

### 版框几何常数（清楚的页实测，2026-09-01）

单位 px，均值 ± 标准差；「清楚」= 内框峰墨 ≥0.45 且外条峰墨 ≥0.60。
「外延」就是金标 `*_outer_offset` 的口径。

| 边 | 页数 | 内框线宽 | 外框条宽 | 内心→外条近沿 | 内心→外条外延 |
|---|---|---|---|---|---|
| 上框 | 4 | 6.5 ± 0.1 | 13.0 ± 6.2 | 17.8 ± 1.4 | 30.8 ± 6.8 |
| 下框 | 5 | 5.6 ± 0.5 | 17.2 ± 2.1 | 16.7 ± 0.8 | 33.9 ± 2.1 |
| 竖直（纸边侧）| 5 | 4.6 ± 0.4 | 19.2 ± 1.2 | 20.6 ± 2.7 | 39.8 ± 3.3 |

两条要点：

- **版框四边不等距。** 同页实测，竖直的外延间距比上框大 **10.8±4.5px**、比下框大
  **5.9±4.2px**（n=5）。先前文档里写的「内外间距全页一致 38.4±4.0px」只对**竖直**
  成立，套到上下会整体偏外。
- **外条近沿不可用，只有远沿（外延）是稳的。** 外条是从**内侧**磨掉的：清楚页近沿
  在 +15~+17，磨损页漂到 +28~+34，而远沿只从 +33~+38 漂到 +39~+45。**别拿近沿去
  反推内框位置**——这是量过的负结果。

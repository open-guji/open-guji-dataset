# 界行三段折线金标

`VLine` 的三段折线 `(x, k1, k2, k3)` + 折点 `y1/y2`，逐段人裁。
**线号从右到左、从 1 开始**，跟 `BorderDetectionResult.verticals` 的顺序一致
（`verticals[0]` 最右）。再生：open-guji-cv 的
`scripts/export_vline_polyline_gold.py`；看图：`scripts/draw_polyline_overlay.py`。

## 被拒 7 段的根因（已查清，两种病）

**病一：折点搜索半径不够**（vol01/119 L3 段3、L4 段1）。真墨离直线中位 23px
（到 33）和 18.5px（到 55），而 `KNOT_SEARCH` 原来是 24，折点够不着。
扫 24/40/60 后定 40：这两段 w80 19→15、22→13，离真墨 24→8px、28→7px；
60 再无收益，对照页 vol01/151、11、24、vol02/95 一个数都没变。**已修**。

**病二：窗口里压着两条线状墨带**（vol01/11 L1、vol01/119 L1，都是最右那条框线）。
内框细线 + 外框粗条一起落进 ±40px 窗口，合起来墨宽中位 17~21px，被
`BEND_INK_W_MAX=9` 全剔掉，有效行只剩 83/1185 和 46/1197，低于 `BEND_MIN_ROWS`
就退回直线、根本没拟合。
- 补救：拟合失败的线**借同页已拟合线的折点位移中位数**（同一页的线是一起弯的，
  纸张/雕版形变是整页的）。vol01/119 L1 段3 靠这个从离真墨 20px 修到 1px。**已修**。
- **vol01/11 L1 修不了，因为病在上游**：这条线离 L2 只有 155px，而该页其余列距
  中位 183px——差 28px；宽窗口图上绿线所在处**根本没有细框线**，真正的框是右侧
  那条粗斜带。这是 `find_vertical_lines` 找错了位置，折线拟合无能为力。
  早先另一条路也测到过同一件事（"线上墨 0.162、脊线样本仅 33 个"）。
- **vol01/119 L1 段2 待裁**：补救后从离真墨 3px 变成 10px（略差）。窗口里有两条
  细线 + 一条粗带，机器判不准哪条是真界行，**等人拖金标**。

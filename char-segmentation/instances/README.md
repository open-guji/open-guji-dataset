# char-segmentation / instances —— 单字图块切分质量

## 测什么

列切成单字之后，图块可能有三类毛病（与人工审查用的标记词一致）：

| 标签 | 含义 |
|---|---|
| `clean` | 正例：就是完整的本字，没有别人的墨 |
| `contaminated` | 混入界行竖线 / 版框 / 上下邻字残余 |
| `truncated` | 本字的墨被切掉了一部分 |
| `not_text` | 根本不是字（版框角、整条横线、空格位）|

## 判定原则：只看墨，不看框

**图块多裁一点空白不算失败**——空白不影响下游归一化与识别。所以：
混入 = 多了别人的墨，截断 = 少了自己的墨，**与外接框大小无关**。

逐像素的细粒度指标（`keep_recall` / `drop_precision`）在合成数据集
[`../cells`](../cells) 上跑——那里能造出逐像素金标，且天然对空白免疫
（两个指标都只统计墨迹像素）。本数据集是**真实图块**，人工给实例级
四分类标签，两者互补而不重复。

## 评的是「自检」，不是「切分」

人工标签描述的是**当前**输出的质量。重跑切分后标签就不再对应，因此它
**不能**当作可自动重跑的切分回归基准。真正能自动化又有用的问题是：

> 管线能不能自己发现坏图块，把它们送进人工审查队列？

所以被测对象是 `CharInstance.flags`，任意 flag 即算「被标记」——驱动
审查的是有没有进队列，不是标了哪个具体原因。

```bash
cd open-guji-cv
python scripts/eval_instance_quality.py ../open-guji-dataset/char-segmentation/instances
```

## 当前基线

```
  clean        (正例) n= 55  被标记   6     11%
  contaminated (缺陷) n=  4  被标记   4    100%
  truncated    (缺陷) n=  2  被标记   2    100%
  not_text     (缺陷) n=  1  被标记   1    100%

缺陷检出率 100%   标记精确率 54%   正例误报率 11%
```

| 层 | flags | 缺陷召回 | 误报 | 精确 | 用途 |
|---|---|---|---|---|---|
| 确定层 | `rule_bar` `edge_blob` `frame_bars` | 29% | 2% | 67% | 成因明确，下游直接自动处理 |
| ＋疑似层 | `wide_gap` `boundary_ink` `off_center` | **100%** | 11% | 54% | 送人工审查队列 |

⚠️ 确定层**不再是零误报**：`vol01/10:2:6` 这个干净的「冬」被 `edge_blob`
误报（1/55）。之前几轮它一直是 0，这一条要盯着。

确定层召回只有 42%，因为那三个判据都不管截断，而缺陷里有 4 个是截断。

误报率从 17% 升到 19% 也**不是检测变差**：第七轮那两个「臣」由 `truncated`
转成 `clean`，分子多了仍被 `off_center` 标记的干净图块（其中一个在第八轮
随列型改判而消失，样本 66 → 65）。
「臣」的墨天然偏在格位右侧，图块裁全了重心照样偏——这是 `off_center` 的
固有代价。

### 截断这一类：补样 → 验证 → 修根因 → 样本又没了

前四轮样本里**一个截断实例都没有**，这条能力一直无从验证。第五轮出现第一个，
第六轮专门补样到 6 个，第七轮其中 2 个（都是横向截断的「臣」）被上游修好、
转成 `clean`，剩 4 个。

这条链子本身就是补样的意义：**样本先把问题钉死，才谈得上修**。补进来的
2 个「臣」暴露的是同一种系统性失败——职名列的「臣」是小字、贴着界行写，
右缘越出「文字带」中位 15px，而图块正是按文字带裁的。第七轮把裁切边改成
「从文字带往外扩、扩到撞上界行为止」，两个「臣」的右半边就回来了。

代价要一起记：**横向截断这一类现在又没有样本了**，`off_center` 的阈值实质
是在已经消失的案例上定的。没验证过的能力不许当作已验证——已记进
`known_limitation`。

补样的抽样线索是「**本字自己的**连通体越出格外的比例」——只保留主体（≥65%）
在本格内的连通体，邻字不计。全书 5826 个有实质墨的格里该量中位 0.009、
99 分位 0.291，补进来的 5 个在 0.32~0.35。

据此补上判据 **`off_center`**（墨的横向重心偏离格心）：`boundary_ink` 只看
上下带，抓得到纵向截断；横向被切时字整个被推到格位一侧，边缘墨量未必高、
但重心明显偏。标注集里 clean 最大 0.088、横向截断的 3 个实例是 0.148~0.339，
**没有重叠**。加它之后截断检出 4/6 → **6/6**，而**误报率不变**（仍 17%）。

### 这一版的数字要连着上游一起读

缺陷从 17/67 降到 11/63，**不是检测器变强了，是切分本身变好了**：
`segment` 加了残余错切校正与界行吸附之后，全书带界行竖线的图块从
23.7% 降到 3.5%（vol02 20.0% → 2.9%）。原来 12 个 `contaminated` 里有
6 个现在已经是干净的本字。

精确率因此从 0.71 掉到 0.52——缺陷基数小了，同样多的误报占比自然升高。
**这不是退步**，看这类比值时必须同时看分母。

### 为什么要按缺陷形状拆开

原先只有一个笼统的 `boundary_ink`（上下边缘带墨量占比）。它分不开两件
事：界行竖线贯穿全高会在边缘带留墨，**顶天立地的高字同样会**。按形状
拆开之后每个判据都对应一种物理成因：

- `rule_bar` —— 细长、近乎满高的**独立**连通体 → 界行/版框竖线混入。
  位置**不限于贴边**：实测混入竖线的 x/W 从 0.08 到 0.96 都有，限定
  「贴边」反而漏掉一半。汉字里没有哪个**独立**部件既满格高又这么细。
- `edge_blob` —— 连通体**整体**落在上/下边缘带内 → 邻字残余。是「整体
  落在带内」而不是「有墨落在带内」，后者会把高字一起冤枉。
- `frame_bars` —— 版框横线。这一条**形状上判不了**：单条满宽扁横条与
  「一」字的 w/W、h/H、笔画厚度变异全都重叠（旧的 `rule_like` 判据正
  因此把 5 个干净的「一」判成了线）。区别只在列**之外**——版框横线横穿
  整版，「一」字停在本列文字带里。所以它去列框左右各探 12px，两侧都还
  在走才判版框。

## 抽样有意偏置——不要把占比读作缺陷率

63 个样本里 38 个从**历史人工审查标记过的问题位置**抽（那些位置值得
复查），25 个从刚性/弹性列随机抽。所以各类占比**不是全书真实比例**，
只能用于比较不同算法在同一批样本上的表现。

（历史标记只有约 60~67% 能对上当前切分的 `page:col:idx`——弹性列改成
顺序编号、切分本身也改过——所以它们只当抽样线索，金标是对**当前输出**
重新目视标注的。）

## 重标记录

图块内容一变，标签就得跟着重看——这是这个数据集的常态，不是意外。

**第一轮**（segment 加入列型分类）：2771 个图块变化，本表命中 15 个，
12 个重标、3 个 ID 消失。当时先测出了一版自相矛盾的报告（官方 benchmark
说 truncated 检出 0%，离线分析说 100%），查下去才发现标签已过期——
这就是「重跑之后先查漂移，再谈数字」这条规矩的由来。

**第二轮**（segment 加入残余错切校正 + 界行吸附）：坐标系整个变了，
67 个里 **59 个内容变化、4 个 ID 消失**，全部对着新输出重标，样本 → 63。

两轮的结论一致：**切分在变好**。第二轮里原来 12 个 `contaminated` 有 6 个
（199:8:3 31:6:10 153:9:12 126:5:2 200:1:3 65:4:10）已经是完整干净的本字。
代价也记下来：3 个原本干净的格位因列相位平移落到了版框横线上
（146:7:20 171:2:15 97:4:9），转成 `not_text`；116:1:8 吃进版框横线转成
`contaminated`。

本批样本**连续两轮都没有 truncated 实例**，也就是说截断检测能力在这个
数据集上从未被验证过。这不代表全书没有截断，只说明这 63 个样本覆盖不到——
已记进 `metadata.json` 的 `known_limitation`，**没验证过的能力不许当作
已验证**。

**第七轮**（chars 的横向裁切边改按界行外扩）：66 个图块**全部变宽**，
ID 一个没丢。逐个重看只有 2 个标签要动——95:1:17 与 109:9:5 由
`truncated` 转 `clean`。没有任何图块新增确定层 flag，说明外扩没把界行
裹进来。缺陷 14 → 12，误报率 17% → 20%（见上文「当前基线」）。

## 标注方法

每个图块渲染成左右对照：左 = 原图带图块边界（黄框）与上下文，
右 = 图块内连通体着色。据此判断有没有多出别人的墨、有没有缺自己的墨。
标注表在 `open-guji-cv/scripts/build_instance_dataset.py` 的 `LABELS`。

---

扩充样本请照 [doc/adding-samples.md](../../doc/adding-samples.md) 的流程做——
那里固化了已经踩过的坑（金标不得循环、判不准标 uncertain、实例 ID 会随切分失效）。

**第八轮**（`cells_from_components` 的闸门不再重判列型）：65 个图块内容
一个没变，只有 `95:1:17` 消失——它所在的列正是「2 格拉开的官衔列」，
改判弹性之后列内序号重排。样本 66 → 65，缺陷仍 12。

**第九轮**（书级格高改由实测字距定 + 格线逐条吸附到字间空隙）：这一轮的
漂移和以往都不同——**格高一变，`page:col:idx` 指向的字本身就换了人**
（`10:2:6` 从「列」变成「冬」），不是同一个字裁得不一样。65 个图块里
49 个内容变化、3 个 ID 消失（都是「空格位落在版框横线上」的 `not_text`，
格线一动就不存在了）。逐个重看改了 5 个标签，样本 65 → 62，缺陷 12 → 7，
检出仍 100%，误报率 19% → 11%。

**教训写进 `known_limitation`**：凡是改动格高/周期这类**尺度**参数，本数据集
必须整体重看，不能只统计「内容变了几个」——内容没变的那些，指向的字也可能
换了。

## review_recrop 分片（2026-08-24）：人工重切的 bbox 金标

进库审查页支持对切错位的图块**拖框重切**（纯几何事件，与选字独立）。
每条重切都是一对金标：`old_bbox` 是切分的实际输出（坏例，patch 图
即按它裁的），`corrected_bbox` 是用户拖出的正确外接框。由
`open-guji-cv/scripts/build_recrop_shard.py` 从 git 历史里捞旧框回流。

- 首批 9 条（vol01 14/15 页）：5 条 `grid_shift`（列尾格整体上飘
  35~55px，**系统性**格线偏移）、3 条 `rule_bar`（最左/最右列吃进
  断续**内边框**）、1 条 `neighbor_residue`。
  模式分析与给切分层的整改诉求见
  `open-guji-cv/.claude/doc/segmentation_border_feedback.md`。
- 回归口径：新切分在这些 (page,col,idx) 上与 `corrected_bbox` 的
  IoU ≥ 0.85；自检口径不变（至少要被 flag）。
- 与其他 seed 一样是**定向富集**，不能读作全书切分错误率。

## self_assess_r1 分片（2026-08-24）：模型自标注，与人工层分开

`self_assess_r1.json` 是**模型自己判读**的 240 格分层样本（用户指示：
先自评、自标注，只把拿不准的交人工），`label_origin: "model"`，
**不进 `expected.json`、不计入 eval_instance_quality 的人工层指标**。
schema 与 expected.json 相同，多两个字段：`stratum`（抽样层）与
`note`（失败说明）。参照图块同样冻结在 `patches/`。

- 抽样：正文金标页上 seed=42 分层抽 240 格 = `rand` 144（均匀随机，
  无偏层）+ `tail` 48（列首/列尾格定向）+ `flag` 48（带 flag 格定向）。
- 判读结果（2026-08-24 用户裁决后定版）：rand 133/143 = **93.0%**
  （Wilson95 [87.6%, 96.2%]，这是全书正文切分正确率的无偏估计）；
  tail 28/48 = 58.3%、flag 36/47 = 76.6%（定向富集层，不能读作全书
  比率）。
- 失败构成（39 格）：**列端渣格当字 30**（版框横条区残渣，几乎全在
  列首/列尾）、混入 7、字身被掩蔽切伤 1、其余为不确定件。此发现已
  回流为切分层的「列端渣格闸」（open-guji-cv `is_end_cell_junk`）。
- 4 格拿不准的已由用户裁决（2026-08-24）：vol02:120:5:20 与
  vol02:126:2:3 判 `truncated` 入分片（这两条 `label_origin: "human"`，
  裁决即人工标签）；vol02:4:6:3（夹注双行，暂不处理）与
  vol02:188:7:2（看不清）**踢出测试集**，不入分片、不进分母。
- 模型标签与人工金标在重叠格上未发现冲突；如后续人工复核推翻某条，
  以人工为准并在「重标记录」登记。

# 怎么定义和准备一个测试集

写给**接手某一步、要从零建它的测试集的人**。已有数据集的增补流程在
[adding-samples.md](adding-samples.md)，这份讲的是更前面一步：**这个测试集
到底该测什么、金标怎么定义、样本怎么抽**。

**当前策略（2026-08 起）：只优化正文页。** 新建的数据集要么只收正文页，
要么把页型标出来分层报。正文页的现成金标在 [`../page-type`](../page-type)
（`page_type == "body"`，vol01 296 页 / vol02 全书 186 页）。

---

## 第一步：先想清楚「测的是能力，还是输出」

这是最容易搞错的一步，搞错了整个数据集白建。

| | 测**输出** | 测**能力** |
|---|---|---|
| 例子 | 「这一列该切成几格、格线在哪」 | 「管线能不能自己发现这块图切坏了」 |
| 金标挂在 | 图像（页、列、像素）| 当前输出的实例（`page:col:idx`）|
| 重跑算法后 | 仍然成立 | **可能全部失效** |
| 适合 | 几何、版式、页型、逐像素归属 | 自检、置信度、送审队列 |

**只要金标挂在「当前切分产物的编号」上，它就会漂。** 本项目
`char-segmentation/instances` 已经重标 8 轮，每次上游一改，66 个图块全部
要重看。这不是失败，是这类数据集的常态——但你必须**一开始就知道**你选的
是哪一种，并把重标流程写进 README。

能挂在图像上就挂在图像上。`page-geometry`（界行的 x 坐标）和 `page-type`
（这页是什么）算法怎么改都还成立，是最省事的两个。

---

## 第二步：金标定义要能一句话说清，且不含糊

判别定义是**标注与评测共用**的，写得含糊，两边就会各自理解。

写定义时把「**不算**什么」也写出来——这比写「算什么」更能消除歧义：

> `rigid` = 字距 = 1×格高。判据是**字距**，不是字数也不是相位：
> - 一列只有 6 个字、后面全空 → 仍是 `rigid`；
> - 抬头列整体相位偏移但字距未变 → 仍是 `rigid`。

再留两个**状态标签**（不是第三种类别）：

- `blank` —— 客观可判（整列无字），单独计，不进分类指标；
- `uncertain` —— **人工也判不准**，评测**跳过**。

宁可样本少，也不能往金标里灌噪声。实测教训：column-layout 曾错标 3 页，
修正后 body 从 90.4% 升到 96.3%、toc 从 62.2% 降到 58.7%——噪声把两个
方向**同时**带偏了，你根本看不出来是哪边错。

---

## 第三步：主指标要对着**危害**，不是对着方便测的量

先问：这一步做错了，下游到底损失什么？然后**直接量那个损失**。

- 反例：图块裁切用 `rule_bar`（有没有混进界行）当指标，看着 0.2% 完美，
  同时它正在**静默切掉 44.8% 的字的笔画**——所有 flag 都不报。
- 反例：「列数不对」看着像丢了整列，实测**外侧漏墨**反而更低。代理量把
  结论带反了。

**非对称代价必须写进指标。** 两类错误代价不同时，不能只报一个准确率：

> 页型闸门的主指标是 `lost_rate`（该切却跳过 = 静默丢数据），**零容忍**；
> 反向（该跳过却切了）只是产出可标记的垃圾，可以接受。

阈值从**极端样本**定并留 2 倍余量，不从中位定。

---

## 第四步：抽样

1. **按页型/版式分层抽**，别只抽好看的页。页型可用转写文本粗分
   （`臣` 多 → 职名；`卷X` 多 → 目录）**只为保证覆盖，不作为金标**。
2. **两册（或多册）均分**，否则测的是「在某一册上过拟合」。
3. **偏置要写进 metadata。** 本项目 instances 一半样本从历史人工审查
   标记过的问题位置抽——所以各类占比**不是全书真实缺陷率**，只能用于
   同一批样本上比较不同算法。不写清楚，后来人一定会误读。
4. 专门补某一类缺陷时，**抽样线索必须与判据不同**，否则是自证。
   而且线索要卡准：找「截断」时用「连通体越出格外的比例」，第一版没加
   「主体 ≥65% 在本格内」，捞上来的全是**空格位蹭到邻字**——那是污染
   不是截断。

**样本量参考**：本项目现有的可用数据集是 18~394 个样本。几十个就能定出
有用的阈值，前提是覆盖分层、标签干净。

---

## 第五步：标注

**金标不得由被测算法生成**，那是循环论证。渲染判读图时，画的必须是
**独立于算法**的参考——例如判列型时画的是**纯刚性格线**（书级 `cell_h` +
页相位），不是算法切出来的 cell：

```python
y = page_phase
while y < strip.shape[0]:
    cv2.line(strip, (0, int(y)), (strip.shape[1], int(y)), (0, 0, 255), 2)
    y += cell_h
```

**标注表集中在一处。** 本项目的做法是把人工标签写成脚本里的一张
`LABELS` 字典（`open-guji-cv/scripts/build_*_dataset.py`），重跑脚本即可
重建整个数据集。改标注只改那张表，且**改动理由写在表上方的注释里**
（「第 N 轮：因为 X，A 从 clean 转 truncated」）。

每份 `expected.json` **必须**带三个溯源字段：`source_item` /
`pipeline_version` / `label_origin`（`align` | `human` | `synth`）。
对齐标注有噪声，清洗与分层评测都依赖它。

---

## 第六步：报告

数据集目录下放 `metadata.json` + `report.json` + `README.md`：

- `baseline` 是**当前**数字；`baseline_history` 记历史，每条带 `note`
  说明**为什么不可直接相比**（样本变了？分母变了？）。
- **比值类指标要连着分母一起读。** 精确率从 0.71 掉到 0.52 可能不是退步，
  是缺陷基数变小了。报告必须同时给分子分母。
- **分层报的，就分层报，别合成一个数字。** 例：确定层判据（零误报，可
  自动处理）和疑似层判据（有误报，只排人工队列）用途完全不同，合成一个
  数字会同时掩盖两件事。
- `known_limitation` **必须写**。**没验证过的能力不许当作已验证**——
  例如「某类缺陷现在一个样本都没有，所以那条判据的阈值实质是在已消失的
  案例上定的」。
- `relabel_history` 记每一轮重标：`changed` / `dropped_ids` / `effect`。

## 各步骤的数据集与并行分工

| 步骤 | 命令 | 数据集 | 状态 | 能否与别组并行 |
|---|---|---|---|---|
| 版面识别 | `recognize-profile` | [book-profile](../book-profile) | 24，可用 | 能 |
| 页面切分 | `cut` | [cut-page](../cut-page) | 18，可用 | 能 |
| 页型闸门 | `segment` | [page-type](../page-type) | 394 页，可用 | ← 这三个 |
| 版面几何 | `segment` | [page-geometry](../page-geometry) | 39 页，可用 | ← 共用 `grid_segment.py` |
| 行列识别 | `segment` | [column-layout](../column-layout) | 36 页 289 列，可用 | ← **必须串行、同一人做** |
| 格内净化 | `chars` / `seg-bench` | [char-segmentation/cells](../char-segmentation/cells) | 60 合成，可用 | 依赖上面三个的产物 |
| 图块自检 | `chars` | [char-segmentation/instances](../char-segmentation/instances) | 65 真实，可用 | 同上 |
| 归一化 | `normalize` | [char-normalization](../char-normalization) | **0，待建** | **能** |
| 聚类 | `cluster` | [char-clustering](../char-clustering) | **0，待建** | **能** |
| 单字识别 | `label` / `bench-ocr` | [char-ocr](../char-ocr) | **0，待建** | **能** |
| 上下文纠正 | `refine` | [context-correction](../context-correction) | **0，待建** | **能** |
| 参考校对 | `collate` | [collation](../collation) | **0，规划中** | **能** |

判断能否并行只有一条：**会不会改到同一个产物**。
`segment` 那三步都重写 `phase3_char_grid/`，且互为上下游（几何错→列型必错），
必须串行；`chars` 两步改 `extractor.py`，但输入是 `segment` 的产物，上游一动
金标就漂。归一化及其之后的步骤输入是图块、产物各自独立，可以同时开工。

### 并行开工的三条约定

1. **冻结上游产物**：开工前记下 `output/*/phase4_chars/` 当时的 git commit，
   写进评测报告。上游一动，你的金标就漂了。
2. **各自的数据集各自建**，别改别人的。共用的只有原图。
3. **接口契约不许私自改**：`phase3_char_grid` 的列/格 JSON、
   `phase4_chars/index.jsonl` 的字段、`layout_spec.PageLayout`。要改先在
   两个仓库同时改文档。

## 建好之后

评测脚本放在 `open-guji-cv/scripts/eval_*.py`，构建脚本放
`open-guji-cv/scripts/build_*_dataset.py`，两边成对提交。
`metadata.json` 里写上 `eval_command`，让别人能一行跑起来。

更细的踩坑清单见
[`open-guji-cv/.claude/doc/pipeline_handbook.md`](https://github.com/open-guji/open-guji-cv/blob/main/.claude/doc/pipeline_handbook.md) §4。

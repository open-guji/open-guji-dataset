# frame-strip：列端格「去框后」干净度

## 这个分片量什么

刻本的版框横线离列首/列尾字很近，格框一裁**必然**把框线带进图块——
这是物理事实，切分层做不到「框线不进图块」。2026-08-25 用户实审 153 格
（review_r4）后定的口径：

> 大部分错误是最后一个字和下边框距离太近，截一个方框几乎必然带上边框，
> **如果你使用后期算法消掉它的话，那就不算错误截取。**

所以本分片量的不是「切分时有没有碰到框」，而是**产物图块里还剩多少框渣**。
框渣算可后处理的污染，判定口径统一为「去框后」。

## 样本

78 条，全部来自 review_r4 的人工实审（`instances/review_events/`）：

| kind | frame=true（带框） | frame=false（干净） |
|---|---|---|
| tail（列末格 idx=20）| 61 | 8 |
| head（列首格 idx=0）| 7 | 2 |

`main_ink` 是**去框前**产物里字身（最大连通体）的墨量基线。剥框只动与
字身不连通的独立连通体，字身一个像素都不该少——这条是用户定的红线
（「只裁边缘连通渣、绝不删与字身连通的墨」），基线就是它的回归护栏。

未入集：`vol01/24:7:20`、`vol01/34:3:20`——整块是纯框线却判 ok，疑为
连点误触；`unsure` 3 条同样不入。中段格（idx∉{0,20}）的 18 条 bad 属
切分层问题，归 `instances` 分片。

## 指标（`scripts/eval_frame_strip.py`，全自动）

| 指标 | 定义 | 目标 |
|---|---|---|
| 残余率 | 带框组里，图块边缘带内仍有「与字身分离的块」的比例 | → 0 |
| 误剥率 | 干净组里，出现残余判定的比例 | 红线 0 |
| 字保全 | 全体样本字身墨量 ≥ `main_ink` 基线的比例 | 红线 100% |

「与字身分离」= 与最大连通体的垂直间隙 ≥ `DEBRIS_GAP`×块高。标定依据
（r4 的 415 个残余块 vs 46 个字身部件）：残余块间隙 p50=5px/p90=23px，
而「灬」四点、「二」下横这类字身部件 p90=2px——间隙是最强判别量。

## 已知不可修

框线与字**粘连**成一个连通体时（实测 vol01/28:4 「不」下方的栅栏状框
残），按红线不能剥。这类样本残余率算作未修复，由 `frame_bars` /
`boundary_ink` 标记送人工审查，不在本分片里追求归零。

## 负结果：字身侧面的框线断段剥不动（2026-08-25）

首版把残余率压到 19% 后，剩下的 13 条里多数是**字左右两侧**的框线断段
（版框横线被字身挡断后留下的左右两截，与字身**垂直位置重叠**，垂直
间隙判据够不着）。试图对「与字身垂直重叠的块」另立判据时量到：

| 特征（重叠块）| 未修复组 | 干净组的字身部件 |
|---|---|---|
| 面积 p50 | 70 | 179 |
| 高度 p50 | 8 | 24 |
| 宽高比 p50 | 1.1 | 1.0 |
| 贴边距离 p50 | 0.14 | 0.07 |

四个量的分布**全面重叠**，没有可用的分界。强行剥会删掉字的独立部件
（点、撇、偏旁），踩用户红线。因此侧面断段保持不剥，残余率 19% 是
本方法的天花板；这些图块由 `frame_bars` / `boundary_ink` 送人工审查。

# char-segmentation / right-cut —— 右缘穿边笔画救援

## 这个分片在测什么

字压着界行写时，`cell_right_x` 贴界行内缘裁，**捺脚/横尾被齐刷刷切断**
（2026-08-26 用户 r10：「有的整列从右边被剪切」；vol02/168 一页 5 列、
vol02/176「大」的捺、vol02/119「之」的捺）。

金标 = 全书正文页扫描出的**穿边笔画组件**：从格内深处（裁切边内 ≥6px）
一直连到裁切边外（≥4px），高 ≤30px（界行是长竖，排除）、面积 ≥25px
（噪点排除）。51 列、213 个穿边点，每条记 (y, 墨尽头)。

⚠ 扫描时试过两个失败的判据，留档防止倒退回去：
- 「边内 2px 与边外 3px 同时有墨」——量出来 1035 列，全是**界行本身**；
- 加短游程过滤（≤25 行）——顶部命中变成**磨损成点线的界行**与脏页噪点。
  最后立住的是连通体判据（必须从格内深处连出去）。

## 修法（open-guji-cv 侧）

phase4 裁条带前做右缘救援（`widen_right_for_crossing`）：检测穿边组件，
把 sx1 外扩到组件尽头（上限 12px）；外扩带进来的**非穿边**小组件
（磨损界行的点渣）当场清掉；整条界行进来由 strip_side_rule /
归属竖线过滤收拾（各有独立回归）。

## 跑分

```bash
cd open-guji-cv
PYTHONPATH=. python scripts/eval_right_cut.py ../open-guji-dataset/char-segmentation
```

现场重跑 extract_page，穿边点所在格的图块外接框右缘须盖住墨尽头 −2px。
基线（修后首测）：救回 166/175（95%），门槛容 10% 疑难（脏页 vol02/3
的噪点「笔画」、个别极端出头）。无承载格 38 个单列出人工过目。

## 已知局限

- 金标的穿边点按**当前网格**的 cell_right_x 量得，重切后 cell_right_x
  变了要重扫（`--update` 式重冻，注明原因）；
- 只测右缘。左缘（撇尖）尚未扫过，若下游反馈再立；
- vol02/3 是重度污渍页，它贡献的「穿边点」多为噪点，判读时注意。

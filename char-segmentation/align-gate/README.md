# char-segmentation / align-gate —— Step5-d 采信闸回归集

## 这个分片在测什么

锚定成功之后（见 [align-anchor](../align-anchor/README.md)），
`open-guji-cv` `clustering/align_label.py::label_page` 要做逐字对齐：
`difflib.SequenceMatcher` 切出 `equal`/`replace`/`insert`/`delete` 段，
**采信闸**决定哪些段收（`equal` 全收；等长 `replace` 段长 ≤3 且被
`equal` 夹住才收）、哪些整段丢弃。

这个分片测的是**采信闸本身的判据**：给定一列的查询串与原始语料窗口
（**保留换行符**，这是与 `align-anchor` 的关键区别——那边为了锚定用
`build_ngram_index` 天然不在乎换行，这边要测的正是换行符会不会污染
等长判据），期望这一列的哪些字位该收、收成什么 `op`、`char`。

## 2026-09-11 首次建档：换行符清理修复的回归套

用户发现 vol01/vol02 已锚定成功的页里，还有4处"整列消失"（之前的
[03-补gate与数据盘点任务书](https://github.com/open-guji/overview/blob/main/项目进展/图片初步数字化/进度/finished/Step5-字符识别/5d-整理本/03-补gate与数据盘点任务书.md)
诊断出的剩余4处：vol01 p86"蒙"、p88"同"、vol02 p63"天"、p165"本"）。
深挖发现根因分两类，**只有一类能修**：

| 案例 | 根因 | 能不能修 |
|---|---|---|
| vol01:86「蒙」 | 语料异体字「𫎇」夹在 `\n𫎇\n` 里，查询串识字「蒙」——本该是等长 replace，但换行符让两边长度从 1:1 变成 1:3，被误判"不等长"丢弃 | **能修**——`label_page`/`page_reference` 清洗 `window` 换行后修复 |
| vol01:88「同」 | 查询串识别错误（语料对应位置其实是「聞」，"進以聞"被误认成"進以同"），紧跟一大段语料没收录的职名页内容，是真实的不等长 replace | 不能修——是 Step5-a/5-c 识别精度问题，不是 Step5-d 对齐算法的事 |
| vol02:63「天」 | 语料「徽宗全盛時也亦可云識微之士\n矣」，查询串本身识别错误叠加换行符 | 换行符清理能救回（对应语料字「矣」，但识字本身已有误差，`op` 仍是 `replace`） |
| vol02:165「本」 | 查询串列首多出「本用易」3字，语料对应位置无对应内容（`delete`），疑似切分边界多切 | 不能修——疑似 Step3/4 切分边界问题，不是对齐层的事 |

修复：`align_label.py::label_page`/`page_reference` 里 `window = corpus[lo:hi]`
改成 `.replace("\n", "")`——语料带抬头换行，`text`（slots 拼出来的纯字符流）
从不含 `\n`，不清洗的话任何一处"本该equal/等长replace"的位置，只因为
换行符多占位就被误判"不等长"整段丢弃。全书语料扫过，单字被换行夹住的
模式有 733 处，不是孤例。

**全量回归**（vol01+vol02 共300页）：equal 数量零变化（没有任何
equal 位因此丢失），新增 replace 164 字位；另有16页的"位数减少"经查
是纠正了旧版 bug——`difflib` 偶尔会把换行符本身误当"金标字"收录
（两侧碰巧凑够同样长度），新版把这类错标正确剔除，不是退化。

## 反例收录的理由

后两个案例（vol01:88、vol02:165）**故意**收进这个分片——都是"看起来
跟前两个长得很像（单字列消失）、但换行符清理救不了"的反例，防止以后
有人看到"整列缺失"就条件反射地归因成换行符问题，或者放宽采信闸阈值
强行把这两处凑出结果（那样会把识别错字/切分多切的字硬塞进金标，污染
比漏标更严重）。

## 数据结构

`query_text`：该列（非全页）`slots_from_evidence` 拼出的识别候选串。

`corpus_window`：锚定成功后、以该页真实 `offset` 截出的语料窗口，
**保留原始换行符**（不同于 `align-anchor` 分片的 `corpus_window`）。

`expected.chars`：这一列里应该被采信闸收录的字位列表，每条
`{char, op, hyp}`——`char` 是金标（语料字），`hyp` 是识别候选（查询字），
`op` 是 `equal`/`replace`。空列表表示"确认不该收录任何字"（反例）。

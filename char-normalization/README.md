# char-normalization —— 归一化 golden 回归

## 测什么

**切出来的原始字块 → 去残余、居中缩放、笔宽归一，得到 64×64 二值字形图。**

归一化是**纯函数**：同一张图进去必须得到同一张图出来。所以这一层不是排行榜，
是**回归门**——任一样本超出容差就算失败。

它值得单独设一道门，是因为下游的质量几乎完全由它决定：骨架化使同字 F1 从
0.4~0.6 提到 0.63~0.93；而聚类那边实测「墨色两极的同字对 0/40 并不上」，
根子也在这里。

## 两层，别混

| 层 | 含义 | 进回归门？ |
|---|---|---|
| `verified` (32) | 目视确认**归一化做对了**，golden 冻结 | 是，必须全过 |
| `known_defect` (3) | 目视确认**归一化做错了**，只记录当前行为 | 否，单独报 |

**绝不能把错的输出冻成 golden**——那等于把缺陷焊死，以后修好了反而报
「回归失败」。判据只有一条：**归一化有没有做它该做的事**（去残余 / 居中缩放 /
笔宽归一）。输入本身是坏切分（跨列、纵向吃进邻字、被腰斩）不算归一化的错，
那是 [char-segmentation](../char-segmentation) 的账，这类样本进门但带 `note`
说明测的是什么。

## 三个指标各管一件事

| 指标 | 抓什么 | 为什么不能只留一个 |
|---|---|---|
| `pixel_diff_ratio` ≤ 0.01 | 任何像素级改动 | —— |
| `binary_iou` ≥ 0.98 | 墨迹整体位置 / 大小 | 抗锯齿边缘差几个像素不该判失败 |
| `skeleton_endpoint_delta` ≤ 2 | 拓扑：断笔与虚连 | 断一笔只改几十个像素，像素比还在容差内，但字形已经变了——聚类里这就是同字判不成同字的直接原因 |

单测里三条各有一个「改坏了必须报」的用例，包括「像素几乎没动但笔画断了」
那一条。一个永远通过的门等于没有门。

## 抽样：线索必须来自归一化之外

35 个样本，两册均分（vol01 18 / vol02 17），六档线索：

| 线索 | 数量 | 怎么挑的 | 覆盖类别 |
|---|---|---|---|
| `typical` | 6 | 无 flag、`ink_ratio` 0.10~0.22 | —— |
| `ink_heavy` | 6 | **墨迹像素的平均灰度**最低 | `ink_heavy` |
| `ink_light` | 6 | 同上，最高 | `ink_light` / `broken_stroke` |
| `border_residue` | 6 | extractor 的 `rule_bar` / `frame_bars` flag | `border_residue` |
| `neighbor_intrusion` | 6 | extractor 的 `edge_blob` flag | `neighbor_intrusion` |
| `human_contaminated/truncated` | 5 | [char-segmentation/instances](../char-segmentation/instances) 的人工标签 | 混合 |

除 `human_*` 外，每档都要求这一格**有整理本对齐金标字**——不加这条，
`rule_bar` / `edge_blob` 捞上来的全是纯版框横条与空格位（第一轮 18 个带 flag
的样本里 11 个根本不是字）。测「字块带残余怎么归一化」，样本得先是个字。

**「墨色」这个量踩了两次坑，记下来**：

1. 用 `ink_ratio` 当墨色 → 捞上来的 6 个最淡样本 5 个是「一」「二」「三」。
   `ink_ratio` 是墨**覆盖比例**，笔画少的字天然低，量到的是笔画数。
2. 改用「最暗 15% 像素的均值」→ 还是笔画少的字（子/七/于/士/元）：那 15%
   里混着一半背景。
3. 最终用 **Otsu 分出墨迹像素后再求均值**，与笔画数无关。用 Otsu 而不是
   归一化里的 Sauvola——抽样线索不能与被测判据同源。

## 基线（2026-08-23，pipeline `23ee9a5`）

```
回归门：32/32 通过
已知缺陷层：3/3 行为未变
```

三个已知缺陷（详见各样本 `expected.json` 的 `defect`）：

| 样本 | 缺陷 |
|---|---|
| [024](samples/024) | **界行竖线没去掉**。实测这条竖条 `x=133 w=6 h=123/132`（高占 93%），但左右都不贴边（`x+bw=139 < 146`）——`remove_edge_specks` 的 vline 判据要求 `x==0 or x+bw>=w`，内缩 7px 就整条漏网，归一图里它成了独立的一竖，外接框被撑宽、字被压窄 |
| [025](samples/025) | 轻微：邻字残点未去，点在字的外接框内没撑大 bbox |
| [031](samples/031) | 邻字残画没去：金标字是「一」，图块上半还留着邻字底部两笔，归一化把三笔一起缩放，「一」被压到下半 |

第一条是可直接动手的：判据里的「贴边」应该给几像素容差，或者改用
「细长 + 靠边区域内」而不是「严格贴边」。

## 怎么跑

```bash
cd open-guji-cv
python scripts/eval_normalize.py ../open-guji-dataset/char-normalization
# 退出码非 0 = 回归门失败
```

重建（归一化**有意**改动之后必须逐张重看再冻结）：

```bash
python scripts/build_normalization_dataset.py --dataset ../open-guji-dataset/char-normalization
```

## known_limitation

1. **回归门只保证「没变」，不保证「对」**。golden 是目视确认过的当前输出，
   目视能看出「残余没去掉」「笔画被删」，看不出亚像素级的错。
2. **`broken_stroke` 类没有确诊样本**。`ink_light` 那一档是用墨色挑的，
   挑出来的字并没有明显断笔——也就是说，「断笔容忍」这条能力目前
   **一个样本都没验证过**。要补就得先找到独立线索（例如同字实例之间
   连通体数量的差异）。
3. **35 个样本只覆盖两册同一版**（武英殿刻本《四庫全書總目》）。换版换刻工
   的墨色分布完全不同，这道门管不到。
4. **`known_defect` 层的三个样本不进门**，所以缺陷修好时门不会变红——
   只会在报告里出现「行为变了」。看到那行要去更新 golden 与
   `build_normalization_dataset.py` 的 `VERDICTS`。

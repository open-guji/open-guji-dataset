# char-segmentation / truncation —— 字身截断率

## 这个分片在测什么

**格线切进字身多深。** 2026-08-26 用户实审 vol01/50、60 反馈
「问题还是很多，太多截断」——属实，而当时在跑的 12 道闸**一道都没报**。

量法：列投影上取「单字墨段」（高 0.45~1.35 格；太短是碎屑，太长是上下
粘连），看有没有格线落在段内、切进去多深，深度按**本段高度**归一：

    截断深度 = min(格线 - 段顶, 段底 - 格线) / 段高

主口径 **≥10% 字高**；同时报 ≥5% / ≥20% / ≥30% 四档，以及**页级分布**
（缺陷按页扎堆，全书率会把「几页烂透」平均掉）。

## 为什么旧尺子看不见

| 旧尺子 | 量的是什么 | 为什么漏 |
|---|---|---|
| `eval_seam` 重切缝 | 平滑列投影在格线那一行的墨量比值 ≥0.7 | 字上缘常只有一横的两端，切下去平滑后比值上不了 0.7；vol01/60 它只报 16.4%，实际 91.8% 的字被切 |
| 抽样正确率（r2~r4） | 「这一格装的是不是一个完整的字」 | 缩略图上削掉 10~20px 的边看不出来，一路判成 clean，报到 99.25% |

**一句话：两把尺子都在量「这一格像不像一个字」，没有一把在量「字被切掉了多少」。**

## 跑分

```bash
cd open-guji-cv
PYTHONPATH=. python scripts/eval_truncation.py ../open-guji-dataset/char-segmentation
```

回归口径：≥10% 与 ≥20% 的条数都不许涨，页级 ≥25%、≥50% 的页数也不许涨。

## 已知局限

- **只看切没切进字身**，不看丢字（`check_grid_offpage`）、不看一格装两字
  （recrop / instances）。三件事要分开看，别拿一条当全部；
- 「单字段」靠高度窗切出来，上下粘连成一坨的地方（浓墨页）会被排除在外，
  所以这条尺子在最脏的页上**偏乐观**；
- 不是 `snap_bounds_to_gaps` 的直接优化目标（那个优化格线处的平滑墨量），
  所以能守也能证；但与 seam 有相关，两条一起看。

# char-segmentation / instances —— 单字图块切分质量

## 测什么

列切成单字之后，图块可能有三类毛病（与人工审查用的标记词一致）：

| 标签 | 含义 |
|---|---|
| `clean` | 正例：就是完整的本字，没有别人的墨 |
| `contaminated` | 混入界行竖线 / 版框 / 上下邻字残余 |
| `truncated` | 本字的墨被切掉了一部分 |
| `not_text` | 根本不是字（版框角、整条横线、空格位）|

## 判定原则：只看墨，不看框

**图块多裁一点空白不算失败**——空白不影响下游归一化与识别。所以：
混入 = 多了别人的墨，截断 = 少了自己的墨，**与外接框大小无关**。

逐像素的细粒度指标（`keep_recall` / `drop_precision`）在合成数据集
[`../cells`](../cells) 上跑——那里能造出逐像素金标，且天然对空白免疫
（两个指标都只统计墨迹像素）。本数据集是**真实图块**，人工给实例级
四分类标签，两者互补而不重复。

## 评的是「自检」，不是「切分」

人工标签描述的是**当前**输出的质量。重跑切分后标签就不再对应，因此它
**不能**当作可自动重跑的切分回归基准。真正能自动化又有用的问题是：

> 管线能不能自己发现坏图块，把它们送进人工审查队列？

所以被测对象是 `CharInstance.flags`，任意 flag 即算「被标记」——驱动
审查的是有没有进队列，不是标了哪个具体原因。

```bash
cd open-guji-cv
python scripts/eval_instance_quality.py ../open-guji-dataset/char-segmentation/instances
```

## 当前基线

```
  clean        (正例) n= 46  被标记   3      7%
  contaminated (缺陷) n= 16  被标记   0      0%     ← 零检出
  truncated    (缺陷) n=  2  被标记   0      0%     ← 零检出
  not_text     (缺陷) n=  6  被标记   3     50%

缺陷检出率 12%    标记精确率 50%    正例误报率 7%
按列型：rigid 缺陷 21 检出 14% / elastic 缺陷 3 检出 0%
```

结论很直接：**混入与截断两类当前完全没有检测器**。管线现有的三个 flag
（`suspect_empty` / `rule_like` / `bad_seg`）只覆盖到 not_text 的一半。
缺陷总检出率 12%，意味着绝大多数坏图块会悄无声息地流进下游。

## 抽样有意偏置——不要把占比读作缺陷率

70 个样本里 42 个从**历史人工审查标记过的问题位置**抽（那些位置值得
复查），28 个从刚性/弹性列随机抽。所以各类占比**不是全书真实比例**，
只能用于比较不同算法在同一批样本上的表现。

（历史标记只有约 60~67% 能对上当前切分的 `page:col:idx`——弹性列改成
顺序编号、切分本身也改过——所以它们只当抽样线索，金标是对**当前输出**
重新目视标注的。）

## 标注方法

每个图块渲染成左右对照：左 = 原图带图块边界（黄框）与上下文，
右 = 图块内连通体着色。据此判断有没有多出别人的墨、有没有缺自己的墨。
标注表在 `open-guji-cv/scripts/build_instance_dataset.py` 的 `LABELS`。

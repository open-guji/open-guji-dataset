# char-segmentation / head-raise-columns —— 列级抬头精标（抬头 / 几格 / 首字被切）

## 这个分片在测什么

**逐列**的三件事，一张卡一起答：

| 字段 | 取值 | 问的是 |
|---|---|---|
| `raised` | `yes` / `no` / `idk` | 这一列是不是抬头（判据：字写到版框线**以上**） |
| `n_raised` | 0~3 | 抬高几格；**只在 `raised == "yes"` 时存在** |
| `head_cut` | `ok` / `cut` / `idk` | **首字有没有被切掉** |

裁决台在控制台 **Step3 页**（`列级抬头精标` 面板），事件
`kind=head_raise`、`target.step=row_segment`，路由表落到本分片。

## 为什么跟 `border-detection/head-raise-presence` 分开

那个是**页级**（整页横带，判「这页有没有抬头」），量的是 Step1 抬头框
探测器 `detect_head_raise()` 的召回率。本分片是**列级**，锚点粒度不同
（页 vs 列），塞一个分片里 eval 口径会打架。两级配合用：页级粗筛找出
抬头页 → 只对判 `yes` 的页出列级卡精标。

## 为什么单开一个 kind 而不是复用 `verdict`

路由表里 `verdict` + `target.step=row_segment` 已经被占着，会把列级抬头
一并灌进 `char-segmentation/row-boundaries`——**那个分片是旧坐标系、已退役**。

## `head_cut` 为什么挂在抬头卡上

它不是抬头的属性，是顺带收的**丢字**维度。2026-09-12 实测：vol02 p11 c4
应是「御定易經通注」，Step3 产物里 `slot 1` 直接是「定」；c5 应是
「御纂周易折中」，`slot -1` 是「纂」——**首字「御」没进任何格子**。同版式
的 c6 却完整。

链路是三层叠加：Step1 抬头框在 vol02 零召回（188 页探到 0 个）→ 闸的
`top_slack` 退化成顶格兜底 → Step3 弹性 DP 首锚点窗口开不上去 → 首字切在
格外。

**为什么必须在这里收**：Step9 渲染出来的文本读着通顺、不报 `[[…]]` 阙文，
**丢字在文本层完全看不见**，这张卡是目前唯一能量到它的入口。别为它单开
一轮标注。

## 口径

- 卡片图是**一列**上版框那一段的原图，`HEADCOL_UP/DN = 330/400` 像素，
  左右各多带 `HEADCOL_SIDE = 18` 像素的邻列便于比高低。
- **叠三层几何线**（用户 2026-09-12 定，与页级 `head` 卡口径相反）：
  蓝＝整页上内边框、橙虚线＝本列抬头内边框（没画=Step1 没探到）、
  红＝格子切分线（`quad_page` 上沿）。

  页级卡刻意不叠，因为那道题问「有没有」，卡上印了机器判断人就会顺着点。
  但列级这三问**不叠线根本答不了**——「抬高几格」要看得见切分线才数得出
  格数，「首字是否完整」要看得见版框线才知道字是不是被切在框外。第一版
  没叠线，实测反馈就是「无法判定几格、首字是否完整」。
  叠加可关（`overlay=0`），想核对线本身画得对不对时用。
- id 形态 `headcol:{book}:{page}:{col}`。前缀**不能带连字符**：
  `harvest._ID_PATTERNS` 的前缀段是 `[a-z_]+`。
- 裁决台在控制台 **Step3 页「抬头标注」卡**，与页级标注同卡两 tab。

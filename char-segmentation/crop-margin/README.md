# crop-margin —— s3 裁边残留空白纸边

## 这个分片量什么

s3 把页面裁到「版框外缘」，正常情况下裁完之后图像四边应该几乎不留
空白（干净页实测残留 0~25px）。但边框磨损重的页，`content_bounds`
的外框线检测会彻底找不到线，退化成「没找到就当图像边缘是边框」——
那一侧完全不裁，残留一大片扫描空白纸边。

来源：2026-08-27 用户提出「先裁后增强」的顺序实验（针对
`char_clustering_design.md` 里「浓墨粘连」截断专题），查证顺序本身
没错，但顺藤查出这个上游裁剪失手的问题。

## 为什么不需要人工标注

残留是图像里客观可数的东西——裁剪之后从图像边缘向内数，墨密度
（`< 128` 阈值下的暗像素占比）连续低于 0.5% 的区间有多长：

```
top    = 第一行「有墨」之前的行数
bottom = 最后一行「有墨」之后的行数
left / right 同理（按列）
```

超过 `flag_threshold_px`（50px，干净页实测噪声 0~25px，留 2 倍余量）
即记一页残留严重。金标只记「当前每一页残留多少」，回归口径：

- 干净页（<50px）**不许**变脏；
- 已经很脏的页**不许**变得更脏。

## 修复结案（2026-08-28，第二轮：路线 A 整体迁移）

**第一次尝试（同一天早些时候）是负结果**：修法本身（`_find_h_frame`
边缘检测退化时改用墨密度兜底）单页验证 90/90 全修好，但全书重建后
下游一批闸（`truncation`/`seam`/`jiazhu_tail`/`left_cut`/`char_drop`/
`frame_strip`/`recrop`）集体失败——根因是这些闸的金标里存着**旧的
（偏松裁剪下的）绝对页面像素坐标**，裁剪边界一收紧，坐标系跟着变，
金标就量错了地方，不是修法本身有问题。

用户看过新旧裁剪边界的可视化对照（133/135/107 三页整页+局部图）后
确认新边界是对的，拍板走**路线 A：把受影响金标一次性迁移到新坐标系**
而不是回退：

1. 全书 394 页各算一个新旧裁剪的平移量 `(dx, dy)`（`dx` 全书实测恒为
   0，这次修复只动上下方向）；
2. `scripts/rekey_instances.py` 扩展支持按 `(dx,dy)` 平移
   `old_bbox`/`corrected_bbox` 这类存了绝对像素坐标的字段（原来只
   重键 `col`/`idx`，不迁移坐标值）；
3. `left-cut`/`right-cut` 的穿边点 `y` 坐标按同一批 `(dx,dy)` 平移；
4. `frame-strip`/`side-rule` 的墨量基线（`main_ink`/`keep_ink`）
   用当前产物重新冻结（这两个存的是标量，不是坐标，迁移不了，只能
   重量）；
5. `jiazhu-tail` 按同一套重键（`col`/`idx` 序号漂移）。

**迁移后复验**：`frame_strip` 那次触了红线的 31% 字身墨损失完全消失，
剩下的全是 1~25 像素的噪声级差异；`side_rule` 71 条误剥全部消失，只剩
1 像素级的量测抖动；`recrop` 含住+盖墨通过从修复前 32/40 **升到 33/40**
（比修复前基线还好）；`instances` rigid 缺陷检出从 55% 回到 64%（原基线
水平）；`jiazhu-tail` 丢字从 2 个降到 1 个。**`crop-margin` 自身：全书
残留 ≥50px 的页从 93 降到 6**——剩下 6 页里 4 页是左右方向的残留（这次
只修了上下方向，左右是已知的、范围更小的独立缺口）、2 页是封面页
（`vol01/2`、`vol02/2`，页图本身包含大幅周边材料，不适用这条判据）。

**仍未解决、本轮不动的残留**（都追到同一个机制：刚性梳子的长度是
书级常量，裁剪收紧后可用像素窗口变小，梳子末端更容易蹭到窗口边缘）：
`char_drop`（16→29，`OFFPAGE_KEEP` 判据比较对象该从图像高度换成
版框内高度而非直接比图高，需要更细致的验证才敢动）、`truncation`/
`seam` 的整书聚合数字有个位数级的真实小幅变化（不是金标漂移，是
测量本身跟着几何变了）、`left_cut`（87/96→82/96，卡在 90% 及格线
边缘）、`check_grid_offpage`（6 页越界，同一个机制）。详见
`open-guji-cv/.claude/doc/pipeline_handbook.md` §12。

**用户最初想解决的"浓墨粘连"截断问题（vol02/133、135、107 等）依然
没被这次修复解决**——书级共识机制会把这批页的 `cell_h`/`row_phase_rel`
拉回和裁剪修复前几乎一致的值，参见 §11 的负结果记录。这次修复的价值
是独立的：裁剪本身现在是对的，且没有留下上一轮尝试暴露出的大范围
下游数据污染。

## 用法

```
PYTHONPATH=. python scripts/eval_crop_margin.py <dataset>/char-segmentation --intermediate-dir <s3_crop 中间产物目录>
PYTHONPATH=. python scripts/eval_crop_margin.py <dataset>/char-segmentation --intermediate-dir <...> --update
```

`--intermediate-dir` 指向含 `vol01/s3_crop`、`vol02/s3_crop`（或已重建
产物根目录 `vol01/*.png` 等）的目录——`preprocess --keep-intermediate`
的输出。
